2 Overview


This tool builds the inputs of Ecopath with Ecosim (EwE) models of the Western Mediterranean: biomass per Functional Group (FG) for the Ecopath baseline and the Ecosim time series, catch, landings, discards and effort by fleet, fishing mortality, P/B and Q/B, the diet matrix, and a validation against the 1995 Western Mediterranean model. It runs as five R scripts (01 biomass, 02 fisheries, 03 P/B and Q/B, 04 diets, 05 validation) from the page above, or from the R console, and writes everything to one Excel workbook plus review tables.


Biomass first: the starting point is a time series of biomass density per Functional Group — how much of each modeled group is really out there, year by year, for whichever region and time window is configured. Everything else in the wider pipeline (catches, mortality, production, diet) is expressed relative to this density, so getting it right — correctly weighted by survey stratum and area, not just averaged naively — is what lets the rest of the model be trusted.


The biomass step has two layers:


    

  1. A shared, survey-agnostic function library (lib_survey_fg_density_functions.R) - the statistical logic (strata weighting, area weighting, outlier detection, catchability correction) that doesn’t depend on which survey or which study area boundary is being used.
    2. 

  2. One Step-1 driver script, 01_biomass.R, that reads the survey’s raw files, reshapes them into the library’s standardized input format and calls the shared functions. AREA_MODE picks the study area:

      

    • AREA_MODE = "westmed" (default) - MEDITS bottom-trawl data, study area defined by the official GFCM GSA polygons (MODEL_GSAS, set in run_pipeline_demo.R with the years; default GSAs 1–12, the Western Med with Northern Tunisia; MEDITS/MEDIAS data exist for GSAs 1, 2, 5–11). Also incorporates MEDIAS acoustic survey data (Section 9), combined with MEDITS into a single density index, and sources 01b_biomass_unsurveyed.R for the groups the surveys cannot measure (Section 12). Outputs in out_dir/biomass/ and out_dir/plots/biomass/.
      • 

    • AREA_MODE = "custom" - the same MEDITS data with a custom boundary (a shapefile or other polygon file uploaded on the page, a lon/lat box, or a custom GSA grouping; CUSTOM_AREA_TYPE) - useful when the same survey supports a different EwE model with its own footprint. MEDITS-only. Outputs in out_dir/<AREA_NAME>/ (default custom_region), so the two modes never overwrite each other.
      • 

    3.

The pipeline covers several conceptually distinct problems in sequence:


    

  1. Which Functional Group does each species belong to? (Section 4)
    2. 

  2. What study area am I actually working with? (Section 5)
    3. 

  3. Given catch and effort, what’s the correctly-standardized density for each haul? (Section 6, including catchability correction and outlier removal)

  4. Given that, what’s the correctly-weighted density estimate for each FG? (Section 7, Section 8)

2.1 Pipeline flow















Some density steps are conditional: catchability correction only runs if a catchability table is provided, strata weighting only if strata = TRUE (otherwise a simple mean density is used instead), and area weighting is only meaningful with more than one area in scope (with a single custom region, it still runs but is mathematically a formality - see Section 8).


Problems 3 and 4 are the most statistically subtle - a naive average across hauls, or treating every survey estimate as if the gear caught 100% of what was present, can be quietly wrong in ways that matter for the final model.

4 Functional Group matching


Every species caught in a haul needs to be assigned to one of the model’s Functional Groups before its biomass can contribute to an FG-level index. This happens in stages, each one only attempting species the previous stage couldn’t resolve - and at every stage, an ambiguous match (a species or taxonomic rank that could plausibly belong to more than one FG) is flagged for manual review rather than guessed.




4.1 Stage 1 - Direct species-level match


The MEDITS species code is translated to a scientific name via the MEDITS taxonomic list (TM_list), then matched directly against the FG reference table.





Code

fg_lookup_safe <- prepare_fg_lookup(dataframe2)
dt <- match_species_to_fg(dataframe1, fg_lookup_safe)






prepare_fg_lookup() also resolves stanza splits here - a species appearing in more than one FG, where every one of those FGs is exclusive to that single species (a life-stage split, e.g. juvenile/adult), is reduced to one FG automatically. This is a structural rule (detected from the FG table’s own shape), not a text-pattern match on words like “juv.” - so it works regardless of the wording convention any given FG scheme happens to use. A species spanning multiple FGs where at least one of those FGs also contains other species is a genuinely different, ambiguous case and is excluded from automatic matching entirely.






4.2 Stage 1b - Nominate subspecies


Some scientific names are trinomials for the nominate subspecies, where the subspecies epithet repeats the species epithet by taxonomic convention (e.g. “Diplodus sargus sargus” is the nominate subspecies of “Diplodus sargus”). These fail a direct match if the FG reference only has the binomial form.





Code

dt <- match_nominate_subspecies_fg(dt, fg_lookup_safe)










4.3 Stage 2 - Manual overrides


MEDITS species codes that are not in the MEDITS taxonomic list are assigned by hand in medits_manual_overrides.csv (Complementary data/medits_reference_tables/; columns species_code, taxon_name, taxon_rank). Add a row there to assign or correct a code; the run then matches that name to an FG like any other.






4.4 Stage 3 - Taxonomy fallback (genus through phylum)


For species with a resolved scientific name but no FG match, the taxonomy of the species is looked up in FishBase/SeaLifeBase and, when missing there, WoRMS [1], [2] (taxonomy_source = "both", cached in FISHBASE_TAXONOMY_CACHE_PATH and WORMS_TAXONOMY_CACHE_PATH). Ranks are tried from the most specific: genus, family, order, class. Phylum is not used (too broad).





Code

dt <- fallback_match_fg_by_taxonomy(dt, fg_lookup_safe, taxonomy_source = "worms")






Safety rule, applied at every rank: a taxonomic value is only used for fallback matching if it maps to exactly one FG among all species already in the reference table.


\[\text{rank value is safe to use} \iff \left| \{\, FG_i : \text{species}_i \text{ shares this rank value} \,\} \right| = 1\]


A genus spanning multiple FGs (e.g. containing both a small pelagic species and a large predatory one) is too ecologically diverse to assign safely, and is excluded rather than assigned to whichever FG happens to come up first. Ranks are tried in order of specificity - a genus-level match always wins over a broader but explicit order-level rule for the same species, since rank specificity takes priority over whether a mapping happened to be data-driven or explicitly stated.


Two more rules in fallback_match_fg_by_taxonomy():


    

  • FGs whose name matches exclude_fg_regex (default commercial|jellyfish|suprabenthos|macrozooplankton, so also the “Other commercial…” and “No commercial…” FGs) are never a fallback target: they are defined by a species list or by commercial status, not by taxonomy, so a relative of one of their species is not evidence of membership.
    • 

  • An FG holding a single species cannot be reached through an order or class match (single_species_fg_broad_ranks); only a genus or family match can assign a new species to it.
    • 



With allow_majority_vote = TRUE (default FALSE), a rank value shared by several FGs goes to the FG holding most of its species, unless two FGs tie.






4.5 Species not in the FG file


A species with no FG after stages 1–3 (for example a new species in a later survey year, or one missing from FG_WMed_2026.csv) is not assigned by any built-in rule. It is left out of the FG biomass and written to survey_unmatched_for_manual_review.csv (MEDITS) and medias_unmatched_for_manual_review.csv (MEDIAS), with its taxonomy, number of hauls and mean density, most frequent first. To include it, add it to the FG file (or a code to medits_manual_overrides.csv) and rerun. Catch data use the same approach: unmatched species are listed in species_fg_matched.csv (02).






4.6 Match-rate reporting





Code

taxonomy_context <- attr(dt, "still_unresolved_taxonomy")
still_unmatched <- summarize_unresolved_species(dt, taxonomy = taxonomy_context)






summarize_unresolved_species() reports mean biomass and appearance count alongside taxonomy for whatever remains genuinely unmatched, so manual review can be prioritized - a species appearing in hundreds of samples with real biomass matters more than a one-off trace appearance.










5 Study area definition


Every function downstream of FG matching needs to know which “area” each sample belongs to, and needs a polygon layer to compute stratum areas from bathymetry. The shared library doesn’t assume this has to be a set of official GSA polygons - it just needs some polygon layer with an ID column. Two approaches are covered here.




5.1 Approach A - GFCM GSA polygons


The official GFCM GSA shapefile is downloaded once and cached. MEDITS’ own area field already gives each haul’s GSA directly, so no spatial join is needed.





Code

gsa_shp_path <- list.files(gsa_shp_dir, pattern = "\\.shp$", full.names = TRUE, recursive = TRUE)[1]
area_shp <- st_read(gsa_shp_path, quiet = TRUE)
area_shp$gsa_num <- as.numeric(area_shp$SMU_CODE)
area_shp$gsa_num[area_shp$gsa_num %in% c(111, 112)] <- 11   # Western/Eastern Sardinia -> single GSA 11
AREA_ID_COL <- "gsa_num"
FILTER_AREAS <- 1:11























5.2 Approach B - a custom boundary (bounding box or arbitrary shapefile)


The same MEDITS raw data can instead be restricted to a custom footprint that doesn’t correspond to any GSA code - a simple bounding box, or a shapefile for a different EwE model’s own boundary.





Code

CUSTOM_BBOX <- c(xmin = 2, xmax = 8, ymin = 38, ymax = 42)
custom_poly <- st_as_sfc(st_bbox(c(
  xmin = unname(CUSTOM_BBOX["xmin"]), ymin = unname(CUSTOM_BBOX["ymin"]),
  xmax = unname(CUSTOM_BBOX["xmax"]), ymax = unname(CUSTOM_BBOX["ymax"])
), crs = 4326))
area_shp <- st_sf(area_id = 1, geometry = custom_poly)
AREA_ID_COL <- "area_id"

dataframe1 <- filter_samples_by_area(dataframe1, area_filter = CUSTOM_BBOX, filter_type = "bbox")
dataframe1[, AreaID := 1]






filter_samples_by_area(filter_type = "shapefile") works the same way, but takes an sf polygon (or a path to one) instead of a bounding box - for a real, non-rectangular model boundary.












NoteThe sample coverage map shows the full survey context, not just the custom box







plot_sample_map() computes its display extent from the union of area_shp‘s own bounding box and the sample points’ own Lat/Lon distribution - not area_shp’s bbox alone. Passing it the full, unfiltered survey data (before filter_samples_by_area() runs) means the map zooms out to show the complete MEDITS distribution across the whole survey region, with the custom area’s contour highlighted within that context via selected_areas - not a tight, context-free zoom into just the small box itself. Points inside vs. outside the selected area are shown in different colors either way.


A plain bounding box, unlike the GFCM GSA polygons, is not coastline-aware - it can genuinely overlap land. land_on_top = TRUE draws the land basemap after the intensity fill rather than before, so any part of the box that’s actually land is visibly masked - only marine area should read as part of the study region, and a rectangle has no way to exclude land on its own.



















With only one custom area, AreaID is set to 1 for every retained sample - there’s no sub-division unless the boundary is itself split into multiple named sub-zones. Every function further downstream (strata weighting, area weighting, Excel export) works identically either way; they only ever see whatever AreaID/area_shp combination they’re given, never assuming GSA-specific structure.










6 Per-haul density and corrections




6.1 Swept area


Trawl catch weight on its own isn’t comparable between hauls - a haul that swept more seafloor will naturally catch more, independent of true fish density. Standardizing to a density (weight per unit area swept) is what makes hauls comparable at all.


\[A_{\text{swept}} = \text{distance towed} \times \text{net wing opening}\]


so the haul density is \(d = C / A_{swept}\), with \(C\) the catch of the species in the haul (kg) and \(A_{swept}\) in km².





Code

WING_OPENING_UNIT <- "decimetres"
ta_swept <- ta %>%
  mutate(
    wing_opening_m = if (WING_OPENING_UNIT == "decimetres") wing_opening / 10 else wing_opening,
    swept_area_km2 = (distance * wing_opening_m) / 1e6,
    mean_depth = (shooting_depth + hauling_depth) / 2
  )
dt <- compute_sample_densities(dt)   # Density := Biomass / Effort






The unit for wing_opening (decimetres, not metres) isn’t documented directly in the raw data - confirmed by cross-checking against vertical_opening, a constant 20 across hauls using the standard MEDITS GOC73 trawl gear. 20 decimetres = 2.0m matches GOC73’s real vertical opening; 20 metres would be absurd for a bottom trawl.






6.2 Depth-stratum assignment


MEDITS is a stratified-random survey design: the sampling area within each GSA (or custom region) is divided into 5 standard bathymetric strata.





Code

MEDITS_STRATA <- data.table(
  stratum_num = 1:5,
  depth_min = c(10, 50, 100, 200, 500),
  depth_max = c(49.9999, 99.9999, 199.9999, 499.9999, 799.9999)
)
dt <- assign_depth_stratum(dt, MEDITS_STRATA)






assign_depth_stratum() supports three input shapes: no Stratum column at all (fully derived from depth), a Stratum column already fully populated (used as-is, no derivation attempted), or a partially populated one - existing values are kept, only the missing ones are derived from depth. Hauls with a mean depth outside 10-800m don’t belong to any of the 5 standard strata and are excluded from the strata-weighted index, rather than force-assigned to whichever edge stratum happens to be closest.






6.3 Catchability correction


Trawl surveys don’t catch 100% of what’s actually in the swept area - some individuals escape under, over, or around the net. The raw survey density is a systematic underestimate of true density by an amount that varies by species. Catchability (\(q\), typically \(0 < q \le 1\)) corrects this:


\[D_{\text{true}} = \frac{D_{\text{raw}}}{q}\]


where \(D_{raw}\) is the survey density (catch / swept area, kg/km²), \(q\) the species catchability and \(D_{true}\) the corrected density.





Code

catchability_raw <- fread(CATCHABILITY_CSV_PATH)
CATCHABILITY_TABLE <- catchability_raw[, .(ScientificName = species, q = q_FACTOR)]
dt <- apply_catchability_correction(
  dt, CATCHABILITY_TABLE, default_q = 1,
  species_taxonomy = species_taxonomy, exempt_fg_names = EXEMPT_FG_NAMES
)






Real catchability tables mix true species binomials with broader taxonomic-group entries (e.g. “Isopoda”, “Hydrozoa” - order/class names) and genus-level “spp” entries (“Cirolana spp”, meaning any species in that genus). apply_catchability_correction() classifies each table entry by its apparent level from its text shape and resolves species against it in order of specificity - genus before order, order before phylum - so a genus-level match always wins over a broader but explicit rule for the same species. For species matching nothing in the table at any level, a taxonomic-proximity fallback looks for other species already in the table sharing genus, then family, then order, and borrows the average of their \(q\) rather than falling straight to a generic default.


exempt_fg_names/exempt_species force \(q=1\) (no correction) regardless of anything else resolved - for groups a bottom trawl isn’t designed to sample representatively at all (pelagic, planktonic, seagrass/algae FGs), where “catchability” as a concept doesn’t apply the same way.






6.4 Sample-level outlier detection


A single anomalous haul (a recording error, misidentification or unit mismatch) can distort a year’s FG density. remove_sample_outliers_haul() (OUTLIER_METHOD = "haul", default) screens each species × haul before any aggregation, so only that one observation is affected.


\[
\text{flag}_{s,k} \iff \log(1 + d_{s,k}) > Q_3 + 3\,\text{IQR}
\]


where \(d_{s,k}\) is the density of species \(s\) in haul \(k\), and \(Q_3\) and IQR are the third quartile and interquartile range of \(\log(1+d)\) over the positive hauls of the same species in the same GSA, depth stratum and year (pooled over strata when that cell has fewer than 10 positive hauls; not judged with fewer). The factor 3 is Tukey’s “far out” fence [3].


    

  • Only high values are flagged; zeros and low catches are the normal shape of trawl data.
    • 

  • If 2 or more hauls of the same species in the same GSA × year cross the fence, none is flagged: that is a real aggregation or a good year.
    • 

  • A whole year is never removed.
    • 



This is not a rule of the MEDITS protocol: the MEDITS manual [4] sets how hauls are made and recorded, not how to screen densities. The IQR fence follows the boxplot convention of the MEDITS quality-check tools (RoME), with a stricter fence (3 IQR instead of 1.5) and high values only. In the 2026-10-22 run it flagged 0.98 % of observations (5,130 of 525,426).


DROP_OUTLIERS = FALSE reports flagged observations without removing them. Each flagged observation (species, GSA, year, haul, value, typical value) is written to survey_outliers_flagged.csv; survey_outlier_diagnostic.png and the validation report show their effect.










7 Strata-weighted density (within an area)


This is the central statistical correction in the pipeline. A simple mean density across all hauls in an area implicitly assumes every haul represents an equal share of that area’s seafloor - but different strata are sampled with different numbers of hauls and cover different fractions of the total area, so an unweighted mean would be biased toward whichever stratum happened to get more hauls that year, independent of how much of the area it actually represents.


The standard stratified-survey estimator instead computes a per-stratum mean, then weights each stratum’s contribution by its true share of the area’s total surveyable area (not its share of hauls):


\[D_{\text{area}} = \sum_{h} \bar{D}_h \times \frac{A_h}{A_{\text{area}}}, \qquad \bar{D}_h = \frac{\sum \text{density in stratum } h}{n_{\text{samples},\,h}}\]


where \(h\) is a depth stratum, \(A_h\) its area (km²), \(A_{area} = \sum_h A_h\) the area of the GSA or custom region, \(n_{samples,h}\) the number of hauls in stratum \(h\) and \(\bar D_h\) their mean density.


The stratum area shares are computed from bathymetry, not from sample counts - a NOAA bathymetry raster is downloaded, clipped to the area’s own polygon (a GSA boundary, or the custom region from Section 5 - compute_strata_area_by_area() doesn’t need to know which), and each cell’s real area (latitude-corrected, since grid cells shrink toward the poles) is summed within each depth stratum.





Code

strata_area_by_area <- compute_strata_area_by_area(
  area_ids = FILTER_AREAS, area_shp = area_shp, area_id_col = AREA_ID_COL,
  strata_def = MEDITS_STRATA, cache_path = file.path(out_dir, "strata_area_by_area.csv")
)
n_samples_by_stratum <- dt[!is.na(Stratum), .(n_samples = uniqueN(SampleID)), by = .(AreaID, Year, Stratum)]
per_group_fg <- compute_fg_densities_by_stratum(dt, strata = STRATA)
fg_index <- weight_by_strata(per_group_fg, n_samples_by_stratum, strata_area_by_area)
















Noten_samples must come from the full dataset, never a species/FG-filtered subset







per_group_fg deliberately does not compute its own sample count - a species/FG-specific count would only include samples where that group had non-zero catch, understating true sampling effort (a sample where a species was genuinely absent still counts toward the denominator in a proper mean-density estimator, contributing a true zero). The one correct source of n_samples is n_samples_by_stratum, computed from the full dt (every species/FG together). Using the wrong source here was confirmed, via a hand-calculated test, to produce up to a 4x overestimate for a species caught in only 1 of 4 hauls at a stratum.























8 Region-wide aggregation (across areas)


Section 7 gives a correctly-weighted density per area. Combining multiple areas into a single region-wide estimate has exactly the same weighting problem one level up: areas differ substantially in total surveyable area, so a simple mean of per-area densities would implicitly treat a small area as equally representative of the region as a large one.


A single-stage estimator combining every (area, stratum) cell directly - using each cell’s absolute area, not its proportion within its own area - avoids any double-weighting error from compounding two separate weighting stages:


\[D_{\text{region}} = \frac{\sum_{a,h} \bar{D}_{a,h} \, A_{a,h}}{\sum_{a,h} A_{a,h}}\]


where \(a\) is an area (GSA), \(h\) a depth stratum, \(\bar D_{a,h}\) the mean haul density in that cell and \(A_{a,h}\) its area (km²).





Code

fg_index_regional <- weight_by_area(fg_index)






This is the version used for Ecopath/Ecosim-facing outputs - the per-area index (Section 7) is retained separately for area-level plots and comparisons, where seeing individual areas is the point.


Zero catches count. The sum in the denominator runs over every cell sampled in that year, whether or not the FG was caught there; a cell without the FG contributes \(\bar{D}_{a,h} = 0\). Dividing only by the area where the FG was caught would ignore the zeros and inflate patchy or depth-restricted FGs (median ×1.7 across MEDITS FGs, up to ×90 for groupers). The same rule applies to the species index (weight_species_by_area()) and to MEDIAS (denominator = area of all GSAs surveyed that year). Cells not sampled in a year are left out of both sums, so the estimate is the mean over the sampled area.


GSAs and strata not sampled in a year (SURVEY_IMPUTE_UNSAMPLED_CELLS = TRUE, impute_unsampled_cells()). Every valid haul is kept; only outliers are removed.


    

  • Unsampled GSA. A GSA with no haul in a year is left out of that year. The density is the biomass of the sampled GSAs divided by the area of those GSAs: \(D_y = \sum_{c \in G_y} m_{c,y} A_c / \sum_{c \in G_y} A_c\), where \(G_y\) is the set of cells of the GSAs sampled in year \(y\). Nothing is interpolated into a GSA from other GSAs. Examples: GSA 5 in 1994, 2000 and 2003; 2022, when only GSAs 7–8 were sampled.
    • 

  • Unsampled stratum inside a sampled GSA. It is filled from the same GSA with a multiplicative stratum × year model fitted on that GSA’s sampled cells: \(\hat m_{c,y} = a_c\, b_{g,y}\). Here \(a_c\) is the cell level and \(b_{g,y}\) the year level of GSA \(g\), fitted by alternating least squares. This is the classic missing-cell estimate of a two-way layout [5], in multiplicative form.
    • 

  • Partial-coverage years are kept (ECOSIM_MIN_AREA_COVERAGE = 0).
    • 

  • ASSUMPTION: the mean over the sampled GSAs represents the year. In a year with few GSAs (2022: 14 % of the area), the value reflects those GSAs only. The spike filter still applies.
    • 



Model area (MODEL_AREA_BASIS = "whole_gsa", MODEL_GSAS = 1:12). \(A_{model}\) is the whole sea area of GSAs 1–12, from the coast to the bottom: GSAs 1–11 (Western Mediterranean) plus GSA 12 (Northern Tunisia), which the MSFD includes in the Western Mediterranean subregion (GSA polygons ≈ 843,000 km²; GSAs 3 Southern Alboran ≈ 22,300 km², 4 Algeria ≈ 129,800 km² and 12 Northern Tunisia ≈ 38,300 km² included; the exact value is computed from NOAA bathymetry at run time and written to model_area_by_gsa.csv). MEDITS and MEDIAS survey GSAs 1, 2, 5–11 only. ASSUMPTION (project decision): the survey density per km² of the surveyed GSAs holds for GSAs 3, 4 and 12, so it is applied to the whole \(A_{model}\); for small pelagics the unsurveyed GSAs take the median shelf density of the surveyed ones, and the MEDIAS shelf ratio uses the 10–200 m shelf of all model GSAs. Catch of every coastal state of the model GSAs is kept (Spain, France, Italy, Morocco, Algeria, Tunisia). Tunisia’s catch is its GFCM catch in the Western Med divisions (37.1.1–37.1.3, i.e. GSA 12); its effort, like Algeria’s and Morocco’s, is taken as is from the FishMIP Western Mediterranean Sea region file (effort_histsoc_1841_2017_western-mediterranean-sea.parquet), which is already clipped to that region, so no further scaling is applied (EFFORT_SCALE_BY_WESTMED_SHARE can scale a country by its GFCM catch share in 37.1.1–37.1.3 if a national effort file is used instead). ASSUMPTION: the FishMIP region boundary matches GSAs 1–12; Morocco’s Atlantic effort is outside that region. Tunisia’s fleets are the GSA 12 fleets of fleet_register_taxonomy.csv (Artisanal, Longlines, Purse seiners, Trawls n.e.i., plus Recreational), with Tunisia’s gear map in gear_to_fleettype.csv; like Morocco and Algeria it has no FDI data, so its fleet shares come from the GFCM fleet register or SAU, and its effort technology-creep multiplier is 0.7 (tech_creep_country_multiplier.csv). MEDITS measures 10–800 m. The other depths get AquaMaps pseudo-strata: 0–10 m, 800–1000 m and 1000 m to the seafloor (3,785 m, the deepest point of the Western Med, in the Vavilov Basin of the Tyrrhenian Sea), each scaled from the nearest real stratum by the species’ AquaMaps depth suitability. All bands enter the numerator, and the denominator is the whole area of the GSAs sampled that year: \[\bar D_y = \frac{\sum_{g \in G_y}\sum_{s} \bar D_{g,s,y} A_{g,s}}{\sum_{g \in G_y}\sum_{s} A_{g,s}}, \quad s \in \{0\text{–}10, \text{MEDITS strata}, 800\text{–}1000, 1000\text{–}3785\}\] where \(y\) is the year, \(G_y\) the set of GSAs with data in year \(y\), \(s\) a depth stratum, \(\bar D_{g,s,y}\) the mean density in GSA \(g\), stratum \(s\) and year \(y\), and \(A_{g,s}\) the stratum area (km²).


Ecopath_B, catch per km², F and every 01b group use this same \(A_{model}\) (model_area_by_gsa.csv is read by 02, 03 and 05; the COBALT plankton mean covers all depths of the GSAs). Alternative: MODEL_AREA_BASIS = "medits_10_800" uses only the 10–800 m MEDITS strata (175,660 km² for the surveyed GSAs), with pseudo-strata down to 1000 m.


FGs with no biomass in the Ecopath years. When an FG has no biomass (missing or 0) in YEAR_ECOPATH (1994–1996), its Ecopath_B is the mean of its values over ECOPATH_B_FILL_YEARS (default 1995–2000, every year with data in that window, zeros included): \[B_f = \frac{1}{|Y_f|}\sum_{y \in Y_f} \bar D_{f,y}, \quad Y_f = \{y \in 1995\ldots2000 : \bar D_{f,y} \text{ available}\}\] where \(f\) is the FG, \(\bar D_{f,y}\) its regional density in year \(y\) (t/km²) and \(|Y_f|\) the number of years with data; used when \(B_f > 0\).     •

LIT_AQUAMAPS_EXTEND = FALSE switches this off.

9 MEDIAS acoustic survey


Everything from Section 4 through Section 8 describes MEDITS, the demersal trawl survey - but 01_biomass.R (AREA_MODE = "westmed") also incorporates MEDIAS, the acoustic survey, and combines the two into a single density index rather than keeping them as separate Ecopath/Ecosim sheets. MEDIAS is specifically relevant for small pelagics (sardine, anchovy) that a bottom trawl doesn’t sample well but an acoustic survey does.












ImportantMEDIAS is not part of the sample coverage map (Section 5)







MEDITS data arrives per-haul, with a real lat/lon for every sample - that’s what Section 5’s sample coverage map plots. MEDIAS data arrives already aggregated by country/GSA/year/species (no individual acoustic transect coordinates in the files this pipeline reads) - there’s no per-point geometry to plot for it, so the coverage map only ever shows MEDITS. This isn’t a bug or an oversight to fix; it’s a structural difference in what the two source files actually contain.






MEDIAS differs from MEDITS in several ways that matter for interpreting the combined result, not just in data source:


    

  • No strata weighting, no catchability correction. Section 7 and the catchability step in Section 6 don’t apply here - there’s no per-haul depth to stratify by, and MEDIAS’ own acoustic backscatter-to-biomass conversion already accounts for detectability in a way a MEDITS-style catchability table doesn’t map onto.
    • 

  • A fixed 10-200m depth band, per the MEDIAS Handbook [8] - the acoustic sampling design’s own minimum (10m isobath) and maximum (200m echo-sounding limit), not a modeling choice made in this pipeline.
    • 

  • Official reporting convention is t/nm² (tons per square nautical mile), not the kg/km² MEDITS density work uses elsewhere in this pipeline - converted to t/km² before combining with MEDITS (KM2_PER_NM2 conversion constant), so the two indices are on a comparable footing before averaging.
    •

    •

13 Fisheries — Catches, Landings, Discards, Effort & F (02_fisheries.R)


02_fisheries.R builds the FG × year catch series, its landings/discards split by fleet (Ecopath_L, Ecopath_Di), the effort series, and the fishing mortality \(F\) used by 03_pbqb-traits.R.




13.1 Catch domain


Only catch from the coastal states of the model GSAs is kept (GSA_COASTAL_STATE, from GFCM Res. GFCM/33/2009/2): TARGET_COUNTRIES = Spain, France, Italy, Morocco, Algeria and Tunisia for GSAs 1–12 (override with TARGET_COUNTRIES_OVERRIDE). Catch by countries with no coast in the model GSAs (distant-water fleets) is left out; the 02 log lists the excluded tonnes by country. STECF FDI is filtered to the model GSAs; the fleet register, gear table and FishMIP effort are filtered to the target countries.






13.2 Equations


Indices: \(c\) country, \(f\) FG, \(l\) fleet (country × fleet type), \(y\) year.


    

  1. Species → FG: \(C_{c,f,y} = \sum_{s \in f} C_{c,s,y}\). FAO “NEI” groups are split over candidate FGs in proportion to biomass, with an \(F \le 1\) cap (below). “Marine molluscs nei” (3,814 t/yr in 1994–1996) is split over the commercial mollusc FGs in proportion to the mollusc catch the same country reported to species or group level in the same year, \(C_{nei,f,c,y} = C_{nei,c,y}\,C_{id,f,c,y}/\sum_f C_{id,f,c,y}\) (fallback: the country’s all-year shares, then all countries pooled; mollusc_nei_split_by_country_year.csv). In 1994–1996 the identified mollusc catch was about 44 % cephalopods and 56 % bivalves/gastropods.
    2. 

  2. Catch source (CATCH_FDI_FIRST): for Spain, France and Italy the STECF FDI landings of the model GSAs are used directly in every Country × FG × year FDI reports (2014+); GFCM is used for the years before FDI (incl. 1994–1996) and for Morocco, Algeria and Tunisia. The pre-FDI GFCM years are scaled to the FDI level, \(k_{c,f} = \sum C^{FDI} / \sum C^{GFCM}\) over 2014–2023, so the series has no step at 2014; factors > MAX_CATCH_CALIBRATION_FACTOR (10) are not applied (catch_calibration_factor_capped_REVIEW.csv).
    3. 

  3. Gears with no model fleet (FleetType = EXCLUDED): \(C \leftarrow C\,(1 - \text{share}_{excl,c,y})\), share from FDI (2014+) or SAU (earlier). The removed tonnes are in the 02 log.
    4. 

  4. Discards: \(Di = C \times r\), \(r\) = FDI per-fleet discard ratio, else the FishMIP reported-vs-total ratio by FG × year; \(L = C - Di\).
    5. 

  5. ICCAT (bluefin tuna, swordfish, albacore): Task I nominal catch of the target countries, Mediterranean records only, scaled to the model GSAs by each country’s FDI landings share inside them: \(C^{ICCAT}_{c,sp} \times s_{c,sp}\). Shares in this run: Italy SWO 0.59, BFT 0.57, ALB 0.23; Spain BFT 0.95, SWO 0.89; France 1.
    6. 

  6. Fleet split: \(C_l = C_{c,f,y}\,p_{l,c,f,y}\); \(p\) from FDI (2014+), SAU hindcast bias-corrected to FDI (earlier), else FDI multi-year mean, else country mix, else equal share (flagged).     7. 

  7. Hake stanzas: juvenile share of the catch from MEDITS length frequencies (TC, 1994–1996, model GSAs), \(L(a) = L_\infty(1 - e^{-K(a - t_0)})\) with \(L_\infty\) = 110 cm, \(K\) = 0.178 yr⁻¹, \(t_0\) = 0 [61], \(W = aL^{3.035}\); juvenile = age < 2 yr (\(L\) < 32.9 cm); landings are \(L \ge\) MCRS 20 cm [62], [63]. Result: 55.9 % of landings and 100 % of discards are juvenile (FG 26), applied at fleet level too.
    8. 

  8. Effort (EU): \(E_{l,y} = NE_{c,y}\,\kappa_c\,s_{l,y}\), \(NE\) = Rousseau et al. nominal effort, \(\kappa_c = \sum E^{FDI}/\sum NE\) over the overlap years. With EFFORT_PRIMARY_SOURCE = "rousseau" (default) this one formula is used for every year, so the series has no source change at 2014. FDI is used only for \(\kappa_c\), for the days-per-tonne used in the fleet share \(s_{l,y}\) (catch × days-per-tonne share, rescaled per fleet to the 2014–2016 FDI mean), and to carry the trend after Rousseau’s last year: \(E_y = E_{last}\,E^{FDI}_y / E^{FDI}_{last}\). FDI’s own effort is kept as a check column (2014 Rousseau-based / FDI ratio ≈ 1.14 for France in this run). Before this change, stitching the hindcast to FDI at 2014 gave jumps of up to ×196.
    9. 

  9. Technology creep (effective effort), compounded year by year from the base year \(t_0\) = 2014 (first FDI year): \(E'_t = E_t \prod_{y=t_0+1}^{t}\left(1 + \frac{m_c\,m_s\,r_{g,y}}{100}\right)\) for \(t > t_0\) and \(E'_t = E_t \big/ \prod_{y=t}^{t_0-1}\left(1 + \frac{m_c\,m_s\,r_{g,y}}{100}\right)\) for \(t < t_0\); \(E\) = nominal effort in kW × fishing days (FDI total over vessels, = mean kW × mean days × number of vessels; [64] nominal active effort), \(r_{g,y}\) = annual creep rate (%) of gear \(g\) in year \(y\), \(m_c\) = country multiplier (EU 1, Morocco/Algeria/Tunisia 0.7, ASSUMPTION), \(m_s\) = sector multiplier. Creep is applied to the whole series, including the non-EU years after 2017 where the nominal effort is held at its 2017 value, so effective effort keeps rising. Ecosim uses effort relative to 1995, so the choice of \(t_0\) changes the level but not the trend. Rates: \(r\) = 0.79 %/yr bottom trawl and 2.0 %/yr other gears in 1994–2013 ([65], quoted by [66]), 4.5 %/yr in 2014–2023 ([67], \(C\% = 13.8\,Y^{-0.511}\) at \(Y\) = 9). Sector multiplier: industrial 1.0, artisanal/recreational 0.6 (ASSUMPTION).
    10. 

  10. Ecopath: \(L_{f,l} = \overline{L}_{y \in 1994\text{–}1996} / A_{model}\) (t/km²/yr, same \(A_{model}\) as biomass).
    11. 

  11. Fishing mortality: \(F_f = (\bar C_f / A_{model}) / B_f\), with \(B_f\) = the final Ecopath_B written by 01_biomass.R (survey species density only for FGs without an Ecopath_B). The same \(B_f\) is used by the NEI \(F \le 1\) cap.
    12. 

  12. Ecosim: catch series \(C_{f,y}/A_{model}\); effort series relative to 1995.

15.2 Prey → FG and aggregation


\[
p_{s,d,k} = v_k / \textstyle\sum_k v_k, \qquad DC_{s,j} = \frac{1}{n_s}\sum_d\sum_k p_{s,d,k}\,w_{k\to j}, \qquad DC_{f,j} = \frac{\sum_{s \in f} b_{s|f}\,DC_{s,j}}{\sum_{s \in f} b_{s|f}}
\]


Here \(s\) is a predator species, \(d\) one diet study of that species (\(n_s\) studies in total), \(k\) a prey item in that study with value \(v_k\) (% weight, volume or frequency as reported), \(p_{s,d,k}\) its share within the study, \(j\) a prey FG, \(DC_{s,j}\) the fraction of FG \(j\) in the diet of species \(s\), \(f\) the predator FG and \(DC_{f,j}\) its diet composition. \(w_{k \to j}\) is the share of prey item \(k\) assigned to FG \(j\): prey species in FG_WMed_2026.csv → its FG; else the genus, family, order, class or phylum shared with model species → equal split over the FGs holding that taxon (DIET_TAXON_SPLIT); else a food-category rule (diet_reference_tables/fishbase_food_category_to_fg.csv, about 44 regex rules) → split by Ecopath B of the target FGs (DIET_CATEGORY_SPLIT, ASSUMPTION: prey taken in proportion to availability); else a second pass resolves the prey name through WoRMS and repeats the rank match (cache diet/worms_diet_prey_cache.rds). Fish eggs and larvae go to zooplankton. Detritus/debris items are dropped for predators with FishBase trophic level ≥ 3 (DIET_DETRITUS_MAX_TL, ASSUMPTION: digested remains, not detritus feeding). Non-food items are dropped and the study renormalised. \(b_{s|f}\) = species share of FG biomass (biomass_proportion_by_species_fg.csv from 01).

16.1 STEP A — comparison with the 1995 Western Mediterranean model


Reference: the “estimates” sheet of WMed_EwE.xlsx [98], model area \(A_{old}\) = 846,002 km². Old groups are matched to new FGs through validation_reference_tables/old_to_new_fg_crosswalk.csv (33 rows): several old groups → one new FG are summed (P/B and Q/B biomass-weighted); one old group → several new FGs is compared with the sum of the new FGs.


\[
\text{ratio} = X_{new}/X_{old}, \qquad X_{old}^{(A_{new})} = X_{old}\,A_{old}/A_{new}, \qquad \text{ratio}_{same\ total} = X_{new}/X_{old}^{(A_{new})}
\]


where \(X\) is B (t/km²), P/B or Q/B (1/year) of an FG, \(X_{new}\) this model’s value, \(X_{old}\) the 1995 value and \(A_{new}\), \(A_{old}\) the two model areas (km²); the area rescaling applies to B only. The second form compares the same total tonnes. Flags: ratio outside VALIDATION_RATIO_LOW–VALIDATION_RATIO_HIGH (0.5–2), values appearing/disappearing. In a recent full run about half of the FG × metric rows were flagged (a review prompt, not a verdict). The old sheet has no landings/discards columns, so only B, P/B and Q/B are compared.






16.2 F vs P/Q check (03_pbqb-traits.R)


Because \(P/B = M + F\), a large \(F\) raises P/B and P/Q. For every FG with \(F > 0\), F_vs_PQ_diagnostic_REVIEW.csv gives \(F\), P/B, the part without fishing (\(P/B - F\)), \(E = F/Z\), P/Q with and without \(F\), catch and B, and flags: \(F > 1\); \(F\) alone pushes P/Q above 0.3; \(E > 0.5\) [99]. A flagged FG points to too much catch assigned to it or too little B. Invertebrates have Q/B = 3 P/B, so their P/Q is 0.33 by construction. On the 2026-10-13 data: 14 FGs flagged, 7 with \(F > 1\), and \(F\) pushes P/Q above 0.3 only for groupers (0.52) and bluefin tuna (0.32).

16.5 PREBAL — biomass, P/B and Q/B against trophic level


Before balancing, log biomass and log vital rates should decline steadily with trophic level, with no group far off the line [103], [104]. The trophic level of each FG is computed from the Ecopath_diet sheet:


\[
TL_i = 1 + \sum_j DC_{ij}\, TL_j
\]


where \(DC_{ij}\) is the fraction of prey \(j\) in the diet of predator \(i\) (each diet column rescaled to sum to 1), and \(TL_j = 1\) for primary producers, detritus and any FG with an empty diet column. It is solved by iteration until no TL changes by more than \(10^{-6}\). For each metric \(X \in \{B, P/B, Q/B\}\) the pipeline fits


\[
\log_{10} X_i = a + b\, TL_i + \varepsilon_i
\]


and reports the change per trophic level, \(100\,(10^{b} - 1)\) %, in prebal_slopes.csv. An FG is flagged in prebal_REVIEW.csv when \(|\varepsilon_i| > 2\,s_\varepsilon\) (\(s_\varepsilon\) = standard deviation of the residuals of that metric). Detritus and discards are excluded.


Link (2010) suggests biomass should fall by roughly 5–10 % per TL on the log scale over the whole web; a much steeper slope points to under-estimated top predators or over-estimated low TLs. On the 2026-10-22 run: B −82 % per TL, P/B −55 % per TL, Q/B +5 % per TL. The Q/B slope is flat because the two seabird FGs have Q/B ≈ 72 /year (flagged). Groups with TL = 1 besides producers (corals and gorgonians, meso/micro zooplankton, suprabenthos) have no diet column yet, so their TL is a placeholder — check the diet matrix for them.

.pid_alive <- function() {
  pid <- if (file.exists(.pid_file)) suppressWarnings(as.integer(readLines(.pid_file, warn = FALSE)[1])) else NA
  !is.na(pid) && isTRUE(tryCatch(tools::pskill(pid, 0L), error = function(e) FALSE))
}
.settings_lines <- function() if (file.exists(.settings_file)) readLines(.settings_file, warn = FALSE) else character(0)

## Reopened page: pick up the last run started from here (finished, failed,
## or still going)
if (file.exists(.settings_file)) {
  run_started(file.mtime(.settings_file))
  .st <- grep("^RUN_STEPS", .settings_lines(), value = TRUE)
  run_steps(tryCatch(eval(parse(text = sub("^[^<]*<-", "", .st[1]))), error = function(e) 1:5))
  if (file.exists(.status_file)) {
    run_state(if (identical(readLines(.status_file, warn = FALSE)[1], "done")) "done" else "error")
    run_finished(file.mtime(.status_file))
  } else if (.pid_alive()) {
    run_state("running")
  } else {
    run_state("error"); run_finished(file.mtime(.console))
    run_note("The last run from this page stopped without finishing (R or RStudio was closed?).")
  }
}

observeEvent(input$run, {
  custom <- identical(input$area_mode, "custom")
  if (identical(run_state(), "running")) return()
  if (custom && identical(input$custom_type, "shapefile") && is.null(custom_shape())) {
    showNotification("Upload the region file first.", type = "error"); return() }
  if (!custom && !length(input$gsas)) { showNotification("Select at least one GSA.", type = "error"); return() }
  unlink(c(.status_file, .progress_file, .console, .pid_file))
  writeLines(config_code(), .settings_file)
  Sys.setenv(WMED_PROGRESS_FILE = .progress_file)   # inherited by the Rscript process
  ## The settings block, with the final source() wrapped so the result is reported back here
  body <- config_code()
  body <- body[!grepl("^##", body)]
  body <- sub("^source\\(\"01_biomass.R\"\\).*$", paste0(
    "res <- tryCatch({ cat('--- Step 1/5: 01_biomass.R\\n', file = Sys.getenv('WMED_PROGRESS_FILE'), append = TRUE); ",
    "source('01_biomass.R'); cat('--- Step 1/5 done\\n', file = Sys.getenv('WMED_PROGRESS_FILE'), append = TRUE); 'done' }, ",
    "error = function(e) paste('error:', conditionMessage(e)))"), body)
  code <- paste(c(sprintf("writeLines(as.character(Sys.getpid()), '%s')", .pid_file), sub("^source\\(\"run_pipeline_demo.R\"\\)$",
                      "res <- tryCatch({ source('run_pipeline_demo.R'); 'done' }, error = function(e) paste('error:', conditionMessage(e)))", body),
                  sprintf("writeLines(res, '%s')", .status_file)), collapse = "\n")
  old <- setwd(file.path(.git_dir, "scripts")); on.exit(setwd(old))
  system2(file.path(R.home("bin"), "Rscript"), c("-e", shQuote(code)), wait = FALSE, stdout = .console, stderr = .console)
  run_state("running"); run_started(Sys.time()); run_finished(NULL); run_note(""); step_seen(list())
  run_steps(if (custom) 1L else eval(parse(text = input$steps)))
  showNotification(if (custom) paste0("Biomass step started for '", input$area_name, "' - outputs in out_dir/", input$area_name, ".")
                   else "Pipeline started - progress is shown below the button.", duration = 8)
})

## Progress: read the "--- Step i/5: ..." / "--- Step i/5 done in x min ---"
## lines that run_pipeline_demo.R writes, and estimate the share done from
## the expected minutes per script.
output$run_progress <- renderUI({
  invalidateLater(3000)
  st <- run_state()
  if (identical(st, "idle")) {
    steps <- eval(parse(text = input$steps))
    return(tags$small(class = "text-muted", sprintf("Expected run time about %.0f min (%s).", sum(.step_min[steps]),
                                                   paste(.step_names[steps], collapse = ", "))))
  }
  lines <- if (file.exists(.progress_file)) readLines(.progress_file, warn = FALSE) else character(0)
  started <- as.integer(sub("^--- Step (\\d)/5:.*", "\\1", grep("^--- Step \\d/5: ", lines, value = TRUE)))
  finished <- as.integer(sub("^--- Step (\\d)/5 done.*", "\\1", grep("^--- Step \\d/5 done", lines, value = TRUE)))
  seen <- isolate(step_seen())
  for (k in setdiff(started, as.integer(names(seen)))) seen[[as.character(k)]] <- Sys.time()
  isolate(step_seen(seen))
  steps <- run_steps(); w <- .step_min[steps]
  current <- setdiff(started, finished); current <- if (length(current)) max(current) else NA
  done_min <- sum(.step_min[intersect(finished, steps)])
  cur_min <- if (!is.na(current)) min(as.numeric(difftime(Sys.time(), seen[[as.character(current)]], units = "mins")),
                                      0.95 * .step_min[current]) else 0
  pct <- if (st == "done") 100 else round(100 * (done_min + cur_min) / sum(w))
  elapsed <- as.numeric(difftime(if (is.null(run_finished())) Sys.time() else run_finished(), run_started(), units = "mins"))
  label <- switch(st,
    running = paste0(if (!is.na(current)) paste0("Running ", .step_names[current]) else "Starting",
                     " - ", length(intersect(finished, steps)), " of ", length(steps), " script(s) done - ",
                     sprintf("%.1f", elapsed), " min elapsed, about ", sprintf("%.0f", max(sum(w) - done_min - cur_min, 0)), " min left"),
    done = sprintf("Finished %s, in %.1f min", format(run_finished(), "%d %b %H:%M"), elapsed),
    error = "Stopped with an error - see below")
  colour <- switch(st, running = "bg-info", done = "bg-success", error = "bg-danger")
  ## one chip per script: done / running / waiting
  chips <- lapply(steps, function(k) {
    cls <- if (k %in% finished || st == "done") "bg-success"
           else if (identical(k, current)) (if (st == "error") "bg-danger" else "bg-info")
           else "bg-light text-dark"
    tags$span(class = paste("badge rounded-pill me-1 mb-1", cls), style = "font-size: .95rem; padding: .45em .8em;", .step_names[k])
  })
  tagList(
    tags$div(style = "font-size: 1.15rem; font-weight: 600; margin-bottom: .35rem;",
             switch(st, running = if (!is.na(current)) paste0("Step ", current, "/5: ", .step_names[current]) else "Starting...",
                    done = "Finished", error = "Stopped with an error")),
    tags$div(class = "progress mb-2", style = "height: 34px; border-radius: 17px; font-size: 1.05rem;",
             tags$div(class = paste("progress-bar progress-bar-striped", colour, if (st == "running") "progress-bar-animated"),
                      role = "progressbar", style = paste0("width: ", pct, "%; font-weight: 600;"), paste0(pct, "%"))),
    tags$div(class = "mb-2", chips),
    tags$div(style = "font-size: 1rem;", label))
})

## Overview

This tool builds the inputs of Ecopath with Ecosim (EwE) models of the Western Mediterranean: biomass per Functional Group (FG) for the Ecopath baseline and the Ecosim time series, catch, landings, discards and effort by fleet, fishing mortality, P/B and Q/B, the diet matrix, and a validation against the 1995 Western Mediterranean model. It runs as five R scripts (01 biomass, 02 fisheries, 03 P/B and Q/B, 04 diets, 05 validation) from the page above, or from the R console, and writes everything to one Excel workbook plus review tables.

**Biomass first:** the starting point is a time series of biomass density per Functional Group — how much of each modeled group is really out there, year by year, for whichever region and time window is configured. Everything else in the wider pipeline (catches, mortality, production, diet) is expressed relative to this density, so getting it right — correctly weighted by survey stratum and area, not just averaged naively — is what lets the rest of the model be trusted.

The biomass step has two layers:

1. **A shared, survey-agnostic function library** (`lib_survey_fg_density_functions.R`) - the statistical logic (strata weighting, area weighting, outlier detection, catchability correction) that doesn't depend on which survey or which study area boundary is being used.
2. **One Step-1 driver script, `01_biomass.R`,** that reads the survey's raw files, reshapes them into the library's standardized input format and calls the shared functions. `AREA_MODE` picks the study area:
   - `AREA_MODE = "westmed"` (default) - MEDITS bottom-trawl data, study area defined by the official GFCM GSA polygons (`MODEL_GSAS`, set in `run_pipeline_demo.R` with the years; default GSAs 1–12, the Western Med with Northern Tunisia; MEDITS/MEDIAS data exist for GSAs 1, 2, 5–11). Also incorporates MEDIAS acoustic survey data (@sec-medias), combined with MEDITS into a single density index, and sources `01b_biomass_unsurveyed.R` for the groups the surveys cannot measure (@sec-biomass). Outputs in `out_dir/biomass/` and `out_dir/plots/biomass/`.
   - `AREA_MODE = "custom"` - the same MEDITS data with a custom boundary (a shapefile or other polygon file uploaded on the page, a lon/lat box, or a custom GSA grouping; `CUSTOM_AREA_TYPE`) - useful when the same survey supports a different EwE model with its own footprint. MEDITS-only. Outputs in `out_dir/<AREA_NAME>/` (default `custom_region`), so the two modes never overwrite each other.

Code chunks throughout are **not executed** when this document renders (`eval: false`) - they're shown for reference alongside the explanation, since the pipeline depends on external data files and network access (bathymetry downloads, WoRMS taxonomy lookups) not available at render time. Run the source `.R` scripts directly to reproduce the actual numbers. (The figures are the exception: each one is loaded from your output folder when the page opens, so it always shows the latest run; a figure whose script has not run yet shows a short note instead.)

The pipeline covers several conceptually distinct problems in sequence:

1. **Which Functional Group does each species belong to?** (@sec-fg-matching)
2. **What study area am I actually working with?** (@sec-area-definition)
3. **Given catch and effort, what's the correctly-standardized density for each haul?** (@sec-density, including catchability correction and outlier removal)
4. **Given that, what's the correctly-weighted density estimate for each FG?** (@sec-strata-weighted, @sec-regional)
5. **For the westmed script specifically: how does a second, structurally different survey (acoustic, not trawl) get folded into the same index?** (@sec-medias)

## Functional Group matching {#sec-fg-matching}

Every species caught in a haul needs to be assigned to one of the model's Functional Groups before its biomass can contribute to an FG-level index. This happens in stages, each one only attempting species the previous stage couldn't resolve - and at every stage, an **ambiguous** match (a species or taxonomic rank that could plausibly belong to more than one FG) is flagged for manual review rather than guessed.

### Stage 1 - Direct species-level match

The MEDITS species code is translated to a scientific name via the MEDITS taxonomic list (`TM_list`), then matched directly against the FG reference table.

```{r}
#| label: direct-match
fg_lookup_safe <- prepare_fg_lookup(dataframe2)
dt <- match_species_to_fg(dataframe1, fg_lookup_safe)
```

`prepare_fg_lookup()` also resolves **stanza splits** here - a species appearing in more than one FG, where every one of those FGs is exclusive to that single species (a life-stage split, e.g. juvenile/adult), is reduced to one FG automatically. This is a structural rule (detected from the FG table's own shape), not a text-pattern match on words like "juv." - so it works regardless of the wording convention any given FG scheme happens to use. A species spanning multiple FGs where at least one of those FGs also contains *other* species is a genuinely different, ambiguous case and is excluded from automatic matching entirely.

### Stage 1b - Nominate subspecies

Some scientific names are trinomials for the nominate subspecies, where the subspecies epithet repeats the species epithet by taxonomic convention (e.g. "Diplodus sargus sargus" is the nominate subspecies of "Diplodus sargus"). These fail a direct match if the FG reference only has the binomial form.

```{r}
#| label: nominate-subspecies
dt <- match_nominate_subspecies_fg(dt, fg_lookup_safe)
```

### Stage 2 - Manual overrides

MEDITS species codes that are not in the MEDITS taxonomic list are assigned by hand in `medits_manual_overrides.csv` (`Complementary data/medits_reference_tables/`; columns `species_code`, `taxon_name`, `taxon_rank`). Add a row there to assign or correct a code; the run then matches that name to an FG like any other.

### Stage 3 - Taxonomy fallback (genus through phylum)

For species with a resolved scientific name but no FG match, the taxonomy of the species is looked up in FishBase/SeaLifeBase and, when missing there, WoRMS [@worms2026; @chamberlain2023] (`taxonomy_source = "both"`, cached in `FISHBASE_TAXONOMY_CACHE_PATH` and `WORMS_TAXONOMY_CACHE_PATH`). Ranks are tried from the most specific: genus, family, order, class. Phylum is not used (too broad).

```{r}
#| label: taxonomy-fallback
dt <- fallback_match_fg_by_taxonomy(dt, fg_lookup_safe, taxonomy_source = "worms")
```

**Safety rule**, applied at every rank: a taxonomic value is only used for fallback matching if it maps to **exactly one** FG among all species already in the reference table.

$$\text{rank value is safe to use} \iff \left| \{\, FG_i : \text{species}_i \text{ shares this rank value} \,\} \right| = 1$$

A genus spanning multiple FGs (e.g. containing both a small pelagic species and a large predatory one) is too ecologically diverse to assign safely, and is excluded rather than assigned to whichever FG happens to come up first. Ranks are tried in order of specificity - a genus-level match always wins over a broader but explicit order-level rule for the same species, since rank specificity takes priority over whether a mapping happened to be data-driven or explicitly stated.

Two more rules in `fallback_match_fg_by_taxonomy()`:

- FGs whose name matches `exclude_fg_regex` (default `commercial|jellyfish|suprabenthos|macrozooplankton`, so also the "Other commercial…" and "No commercial…" FGs) are never a fallback target: they are defined by a species list or by commercial status, not by taxonomy, so a relative of one of their species is not evidence of membership.
- An FG holding a single species cannot be reached through an order or class match (`single_species_fg_broad_ranks`); only a genus or family match can assign a new species to it.

With `allow_majority_vote = TRUE` (default `FALSE`), a rank value shared by several FGs goes to the FG holding most of its species, unless two FGs tie.

### Species not in the FG file

A species with no FG after stages 1–3 (for example a new species in a later survey year, or one missing from `FG_WMed_2026.csv`) is **not** assigned by any built-in rule. It is left out of the FG biomass and written to `survey_unmatched_for_manual_review.csv` (MEDITS) and `medias_unmatched_for_manual_review.csv` (MEDIAS), with its taxonomy, number of hauls and mean density, most frequent first. To include it, add it to the FG file (or a code to `medits_manual_overrides.csv`) and rerun. Catch data use the same approach: unmatched species are listed in `species_fg_matched.csv` (02).

### Match-rate reporting

```{r}
#| label: match-rate-reporting
taxonomy_context <- attr(dt, "still_unresolved_taxonomy")
still_unmatched <- summarize_unresolved_species(dt, taxonomy = taxonomy_context)
```

`summarize_unresolved_species()` reports mean biomass and appearance count alongside taxonomy for whatever remains genuinely unmatched, so manual review can be prioritized - a species appearing in hundreds of samples with real biomass matters more than a one-off trace appearance.

## Per-haul density and corrections {#sec-density}

### Swept area

Trawl catch weight on its own isn't comparable between hauls - a haul that swept more seafloor will naturally catch more, independent of true fish density. Standardizing to a **density** (weight per unit area swept) is what makes hauls comparable at all.

$$A_{\text{swept}} = \text{distance towed} \times \text{net wing opening}$$

so the haul density is $d = C / A_{swept}$, with $C$ the catch of the species in the haul (kg) and $A_{swept}$ in km².

```{r}
#| label: swept-area
WING_OPENING_UNIT <- "decimetres"
ta_swept <- ta %>%
  mutate(
    wing_opening_m = if (WING_OPENING_UNIT == "decimetres") wing_opening / 10 else wing_opening,
    swept_area_km2 = (distance * wing_opening_m) / 1e6,
    mean_depth = (shooting_depth + hauling_depth) / 2
  )
dt <- compute_sample_densities(dt)   # Density := Biomass / Effort
```

The unit for `wing_opening` (decimetres, not metres) isn't documented directly in the raw data - confirmed by cross-checking against `vertical_opening`, a constant 20 across hauls using the standard MEDITS GOC73 trawl gear. 20 decimetres = 2.0m matches GOC73's real vertical opening; 20 *metres* would be absurd for a bottom trawl.

### Depth-stratum assignment

MEDITS is a stratified-random survey design: the sampling area within each GSA (or custom region) is divided into 5 standard bathymetric strata.

```{r}
#| label: stratum-from-depth
MEDITS_STRATA <- data.table(
  stratum_num = 1:5,
  depth_min = c(10, 50, 100, 200, 500),
  depth_max = c(49.9999, 99.9999, 199.9999, 499.9999, 799.9999)
)
dt <- assign_depth_stratum(dt, MEDITS_STRATA)
```

`assign_depth_stratum()` supports three input shapes: no `Stratum` column at all (fully derived from depth), a `Stratum` column already fully populated (used as-is, no derivation attempted), or a *partially* populated one - existing values are kept, only the missing ones are derived from depth. Hauls with a mean depth outside 10-800m don't belong to any of the 5 standard strata and are excluded from the strata-weighted index, rather than force-assigned to whichever edge stratum happens to be closest.

### Catchability correction

Trawl surveys don't catch 100% of what's actually in the swept area - some individuals escape under, over, or around the net. The raw survey density is a systematic *underestimate* of true density by an amount that varies by species. Catchability ($q$, typically $0 < q \le 1$) corrects this:

$$D_{\text{true}} = \frac{D_{\text{raw}}}{q}$$

where $D_{raw}$ is the survey density (catch / swept area, kg/km²), $q$ the species catchability and $D_{true}$ the corrected density.

```{r}
#| label: catchability
catchability_raw <- fread(CATCHABILITY_CSV_PATH)
CATCHABILITY_TABLE <- catchability_raw[, .(ScientificName = species, q = q_FACTOR)]
dt <- apply_catchability_correction(
  dt, CATCHABILITY_TABLE, default_q = 1,
  species_taxonomy = species_taxonomy, exempt_fg_names = EXEMPT_FG_NAMES
)
```

Real catchability tables mix true species binomials with broader taxonomic-group entries (e.g. "Isopoda", "Hydrozoa" - order/class names) and genus-level "spp" entries ("Cirolana spp", meaning any species in that genus). `apply_catchability_correction()` classifies each table entry by its apparent level from its text shape and resolves species against it in order of specificity - genus before order, order before phylum - so a genus-level match always wins over a broader but explicit rule for the same species. For species matching nothing in the table at any level, a **taxonomic-proximity fallback** looks for other species already in the table sharing genus, then family, then order, and borrows the average of their $q$ rather than falling straight to a generic default.

`exempt_fg_names`/`exempt_species` force $q=1$ (no correction) regardless of anything else resolved - for groups a bottom trawl isn't designed to sample representatively at all (pelagic, planktonic, seagrass/algae FGs), where "catchability" as a concept doesn't apply the same way.

### Sample-level outlier detection

A single anomalous haul (a recording error, misidentification or unit mismatch) can distort a year's FG density. `remove_sample_outliers_haul()` (`OUTLIER_METHOD = "haul"`, default) screens each species × haul **before** any aggregation, so only that one observation is affected.

$$
\text{flag}_{s,k} \iff \log(1 + d_{s,k}) > Q_3 + 3\,\text{IQR}
$$

where $d_{s,k}$ is the density of species $s$ in haul $k$, and $Q_3$ and IQR are the third quartile and interquartile range of $\log(1+d)$ over the **positive** hauls of the same species in the same GSA, depth stratum and year (pooled over strata when that cell has fewer than 10 positive hauls; not judged with fewer). The factor 3 is Tukey's "far out" fence [@tukey1977].

- Only high values are flagged; zeros and low catches are the normal shape of trawl data.
- If 2 or more hauls of the same species in the same GSA × year cross the fence, none is flagged: that is a real aggregation or a good year.
- A whole year is never removed.

This is **not** a rule of the MEDITS protocol: the MEDITS manual [@medits2017] sets how hauls are made and recorded, not how to screen densities. The IQR fence follows the boxplot convention of the MEDITS quality-check tools (RoME), with a stricter fence (3 IQR instead of 1.5) and high values only. In the 2026-10-22 run it flagged 0.98 % of observations (5,130 of 525,426).

`DROP_OUTLIERS = FALSE` reports flagged observations without removing them. Each flagged observation (species, GSA, year, haul, value, typical value) is written to `survey_outliers_flagged.csv`; `survey_outlier_diagnostic.png` and the validation report show their effect.

## Strata-weighted density (within an area) {#sec-strata-weighted}

This is the central statistical correction in the pipeline. A **simple mean density across all hauls in an area** implicitly assumes every haul represents an equal share of that area's seafloor - but different strata are sampled with different numbers of hauls *and* cover different fractions of the total area, so an unweighted mean would be biased toward whichever stratum happened to get more hauls that year, independent of how much of the area it actually represents.

The standard stratified-survey estimator instead computes a per-stratum mean, then weights each stratum's contribution by its **true share of the area's total surveyable area** (not its share of hauls):

$$D_{\text{area}} = \sum_{h} \bar{D}_h \times \frac{A_h}{A_{\text{area}}}, \qquad \bar{D}_h = \frac{\sum \text{density in stratum } h}{n_{\text{samples},\,h}}$$

where $h$ is a depth stratum, $A_h$ its area (km²), $A_{area} = \sum_h A_h$ the area of the GSA or custom region, $n_{samples,h}$ the number of hauls in stratum $h$ and $\bar D_h$ their mean density.

The stratum area shares are computed from **bathymetry**, not from sample counts - a NOAA bathymetry raster is downloaded, clipped to the area's own polygon (a GSA boundary, or the custom region from @sec-area-definition - `compute_strata_area_by_area()` doesn't need to know which), and each cell's real area (latitude-corrected, since grid cells shrink toward the poles) is summed within each depth stratum.

```{r}
#| label: strata-area-and-weighted-estimator
strata_area_by_area <- compute_strata_area_by_area(
  area_ids = FILTER_AREAS, area_shp = area_shp, area_id_col = AREA_ID_COL,
  strata_def = MEDITS_STRATA, cache_path = file.path(out_dir, "strata_area_by_area.csv")
)
n_samples_by_stratum <- dt[!is.na(Stratum), .(n_samples = uniqueN(SampleID)), by = .(AreaID, Year, Stratum)]
per_group_fg <- compute_fg_densities_by_stratum(dt, strata = STRATA)
fg_index <- weight_by_strata(per_group_fg, n_samples_by_stratum, strata_area_by_area)
```

::: {.callout-note}
### `n_samples` must come from the full dataset, never a species/FG-filtered subset
`per_group_fg` deliberately does **not** compute its own sample count - a species/FG-specific count would only include samples where that group had non-zero catch, understating true sampling effort (a sample where a species was genuinely absent still counts toward the denominator in a proper mean-density estimator, contributing a true zero). The one correct source of `n_samples` is `n_samples_by_stratum`, computed from the *full* `dt` (every species/FG together). Using the wrong source here was confirmed, via a hand-calculated test, to produce up to a 4x overestimate for a species caught in only 1 of 4 hauls at a stratum.
:::

## Region-wide aggregation (across areas) {#sec-regional}

@sec-strata-weighted gives a correctly-weighted density **per area**. Combining multiple areas into a single region-wide estimate has exactly the same weighting problem one level up: areas differ substantially in total surveyable area, so a simple mean of per-area densities would implicitly treat a small area as equally representative of the region as a large one.

A single-stage estimator combining every (area, stratum) cell directly - using each cell's **absolute** area, not its proportion within its own area - avoids any double-weighting error from compounding two separate weighting stages:

$$D_{\text{region}} = \frac{\sum_{a,h} \bar{D}_{a,h} \, A_{a,h}}{\sum_{a,h} A_{a,h}}$$

where $a$ is an area (GSA), $h$ a depth stratum, $\bar D_{a,h}$ the mean haul density in that cell and $A_{a,h}$ its area (km²).

```{r}
#| label: regional-estimator
fg_index_regional <- weight_by_area(fg_index)
```

This is the version used for Ecopath/Ecosim-facing outputs - the per-area index (@sec-strata-weighted) is retained separately for area-level plots and comparisons, where seeing individual areas is the point.

**Zero catches count.** The sum in the denominator runs over **every cell sampled in that year**, whether or not the FG was caught there; a cell without the FG contributes $\bar{D}_{a,h} = 0$. Dividing only by the area where the FG was caught would ignore the zeros and inflate patchy or depth-restricted FGs (median ×1.7 across MEDITS FGs, up to ×90 for groupers). The same rule applies to the species index (`weight_species_by_area()`) and to MEDIAS (denominator = area of all GSAs surveyed that year). Cells not sampled in a year are left out of both sums, so the estimate is the mean over the sampled area.

**GSAs and strata not sampled in a year** (`SURVEY_IMPUTE_UNSAMPLED_CELLS` = TRUE, `impute_unsampled_cells()`). Every valid haul is kept; only outliers are removed.

- **Unsampled GSA.** A GSA with no haul in a year is left out of that year. The density is the biomass of the sampled GSAs divided by the area of those GSAs: $D_y = \sum_{c \in G_y} m_{c,y} A_c / \sum_{c \in G_y} A_c$, where $G_y$ is the set of cells of the GSAs sampled in year $y$. Nothing is interpolated into a GSA from other GSAs. Examples: GSA 5 in 1994, 2000 and 2003; 2022, when only GSAs 7–8 were sampled.
- **Unsampled stratum inside a sampled GSA.** It is filled from the same GSA with a multiplicative stratum × year model fitted on that GSA's sampled cells: $\hat m_{c,y} = a_c\, b_{g,y}$. Here $a_c$ is the cell level and $b_{g,y}$ the year level of GSA $g$, fitted by alternating least squares. This is the classic missing-cell estimate of a two-way layout [@yates1933], in multiplicative form.
- **Partial-coverage years** are kept (`ECOSIM_MIN_AREA_COVERAGE` = 0).
- ASSUMPTION: the mean over the sampled GSAs represents the year. In a year with few GSAs (2022: 14 % of the area), the value reflects those GSAs only. The spike filter still applies.

**Model area (`MODEL_AREA_BASIS = "whole_gsa"`, `MODEL_GSAS = 1:12`).** $A_{model}$ is the whole sea area of GSAs 1–12, from the coast to the bottom: GSAs 1–11 (Western Mediterranean) plus GSA 12 (Northern Tunisia), which the MSFD includes in the Western Mediterranean subregion (GSA polygons ≈ 843,000 km²; GSAs 3 Southern Alboran ≈ 22,300 km², 4 Algeria ≈ 129,800 km² and 12 Northern Tunisia ≈ 38,300 km² included; the exact value is computed from NOAA bathymetry at run time and written to `model_area_by_gsa.csv`). MEDITS and MEDIAS survey GSAs 1, 2, 5–11 only. ASSUMPTION (project decision): the survey density per km² of the surveyed GSAs holds for GSAs 3, 4 and 12, so it is applied to the whole $A_{model}$; for small pelagics the unsurveyed GSAs take the median shelf density of the surveyed ones, and the MEDIAS shelf ratio uses the 10–200 m shelf of all model GSAs. Catch of every coastal state of the model GSAs is kept (Spain, France, Italy, Morocco, Algeria, Tunisia). Tunisia's catch is its GFCM catch in the Western Med divisions (37.1.1–37.1.3, i.e. GSA 12); its effort, like Algeria's and Morocco's, is taken as is from the FishMIP Western Mediterranean Sea region file (`effort_histsoc_1841_2017_western-mediterranean-sea.parquet`), which is already clipped to that region, so no further scaling is applied (`EFFORT_SCALE_BY_WESTMED_SHARE` can scale a country by its GFCM catch share in 37.1.1–37.1.3 if a national effort file is used instead). ASSUMPTION: the FishMIP region boundary matches GSAs 1–12; Morocco's Atlantic effort is outside that region. Tunisia's fleets are the GSA 12 fleets of `fleet_register_taxonomy.csv` (Artisanal, Longlines, Purse seiners, Trawls n.e.i., plus Recreational), with Tunisia's gear map in `gear_to_fleettype.csv`; like Morocco and Algeria it has no FDI data, so its fleet shares come from the GFCM fleet register or SAU, and its effort technology-creep multiplier is 0.7 (`tech_creep_country_multiplier.csv`). `MODEL_GSAS` and `MODEL_AREA_BASIS` are set in `run_pipeline_demo.R` with the years; the default is the whole Western Med, and any subset of GSAs filters the area, the survey data and the catch countries together. MEDITS measures 10–800 m. The other depths get AquaMaps pseudo-strata: 0–10 m, 800–1000 m and 1000 m to the seafloor (3,785 m, the deepest point of the Western Med, in the Vavilov Basin of the Tyrrhenian Sea), each scaled from the nearest real stratum by the species' AquaMaps depth suitability. All bands enter the numerator, and the denominator is the whole area of the GSAs sampled that year:
$$\bar D_y = \frac{\sum_{g \in G_y}\sum_{s} \bar D_{g,s,y} A_{g,s}}{\sum_{g \in G_y}\sum_{s} A_{g,s}}, \quad s \in \{0\text{–}10, \text{MEDITS strata}, 800\text{–}1000, 1000\text{–}3785\}$$
where $y$ is the year, $G_y$ the set of GSAs with data in year $y$, $s$ a depth stratum, $\bar D_{g,s,y}$ the mean density in GSA $g$, stratum $s$ and year $y$, and $A_{g,s}$ the stratum area (km²).

Ecopath_B, catch per km², F and every 01b group use this same $A_{model}$ (`model_area_by_gsa.csv` is read by 02, 03 and 05; the COBALT plankton mean covers all depths of the GSAs). Alternative: `MODEL_AREA_BASIS = "medits_10_800"` uses only the 10–800 m MEDITS strata (175,660 km² for the surveyed GSAs), with pseudo-strata down to 1000 m.

**FGs with no biomass in the Ecopath years.** When an FG has no biomass (missing or 0) in `YEAR_ECOPATH` (1994–1996), its Ecopath_B is the mean of its values over `ECOPATH_B_FILL_YEARS` (default 1995–2000, every year with data in that window, zeros included):
$$B_f = \frac{1}{|Y_f|}\sum_{y \in Y_f} \bar D_{f,y}, \quad Y_f = \{y \in 1995\ldots2000 : \bar D_{f,y} \text{ available}\}$$
where $f$ is the FG, $\bar D_{f,y}$ its regional density in year $y$ (t/km²) and $|Y_f|$ the number of years with data;
used when $B_f > 0$. If the window has no positive mean, the nearest single year with data is used (the earlier rule). Which rule filled each FG is in `ecopath_B_baseline_year_borrowed_REVIEW.csv` (`borrowed_how`). `ECOPATH_B_FILL_MODE = "nearest"` restores the earlier rule. The **Expanding** FGs (range-expanding species, rare or absent at the baseline) are never filled from other years: they get the minimal biomass `ECOPATH_B_EXPANDING_MIN` = 0.00001 t/km² so Ecopath keeps the group, and get no F (catch divided by a placeholder biomass is not a fishing mortality).

**Depth strata.** Bathymetry cells are assigned to strata with `findInterval()` on the stratum lower bounds, so every stratum, including the deepest (501–800 m) and the AquaMaps bands below 800 m, gets its own area.

**AquaMaps occurrence outside the sampled depths.** Every biomass except MEDIAS, stock assessments, plankton models and mapped habitats is extended to depths its source did not sample, scaled by AquaMaps depth suitability:

- *MEDITS* (`lib_aquamaps_depth_extension.R`): pseudo-strata 0–10 m and 800–1000 m, each anchored to the adjacent real stratum's measured density × the suitability ratio. Species with no AquaMaps match at species level take the median envelope of their AquaMaps congeners (`match_method = "genus"`, ASSUMPTION: congeners share a depth range). Before this, 341 of 989 species had no envelope.
- *Literature depth-band densities* (`lit_aquamaps_extension()` in 01b): a density measured over $[z_1, z_2]$ is extended to the other depth bands of the same domain as $D_k = D\, S_k / S_{band}$. Here $S$ is the group's mean AquaMaps suitability over a band (species from `Habitat_species`, else the FG's species), with no double counting between rows of the same group. `LIT_AQUAMAPS_EXTEND = FALSE` switches this off.

**Strata-area caches.** `compute_strata_area_by_area()` reuses a cached CSV only when its strata numbers and depth bounds match the current strata definition and it covers every area. Otherwise it recomputes and keeps the old file as `.stale`. The cache of 2026-10-05 had 4 real strata: stratum 4 carried the 201–800 m area and there was no stratum 5, so every 501–800 m haul was dropped. The AquaMaps cache had the 800–3785 m area under an 800–1000 m label.

**Ecosim trend hygiene** (`01_biomass.R`, STEP 7c and the export). Three rules applied only to the year-to-year shape of the B series, not to `Ecopath_B`:

1. *Haul cap* (`ECOSIM_HAUL_CAP_Q` = 0.95). Each haul's FG density is capped at the 95th percentile of that FG's positive hauls in the same GSA × stratum over all years (only where there are ≥ 10 positive hauls). The capped index $I^{cap}$ is built with the same estimator, and its shape is carried over as $I^{new}_{f,y} = I_{f,y}\, s_{f,y}\, \overline{I_f}^{EP} / \overline{I_f s_f}^{EP}$, with $s_{f,y} = I^{cap}_{f,y}/I^{raw}_{f,y}$ and $\overline{\cdot}^{EP}$ the 1994–1996 mean. So `Ecopath_B` is unchanged. Capping lowers absolute densities by construction, which is why it is not applied to the baseline. `ecosim_haul_cap_effect_REVIEW.csv` lists, per FG, how much the 1994–1996 mean would fall if capped. A ratio ≫ 1 means the baseline rests on a few very large hauls (e.g. commercial small demersal fish, ×6 from one 1995 haul of *Gymnammodytes cicerelus*).
2. *Area coverage* (`ECOSIM_MIN_AREA_COVERAGE`, default 0 = off). A year whose sampled strata cover less than this share of the model area would be left blank. It is off because the area-adjusted index (an unsampled GSA is dropped from both numerator and area) already handles partial years (2022: GSAs 7–8 only, 14 %; 2023: 60 %). The 1994–1996 years are never blanked. Coverage by year: `survey_area_coverage_by_year.csv`.
3. *Spike filter* (`ECOSIM_SPIKE_FILTER` = TRUE, `flag_ts_upward_spikes()`). In every B series (survey, model, literature), a year is blanked when $\log x_y - \text{median}(\log x_{\text{4 nearest years}}) > \max(3 \cdot 1.4826\,\text{MAD}, \log 3)$. This is a one-sided Hampel filter [@hampel1974; @pearson2002]. ASSUMPTION: the window, the 3 MAD and the 3-fold floor are judgment choices. Dips are kept. Removed values: `ecosim_ts_spikes_removed_REVIEW.csv`.

Effect of each rule, tested against the 1995 model's series (simplified MEDITS index without q):

| Version | FGs with a spike > 10× the series median | Negative r with the old model | Median r |
|---|---|---|---|
| Zeros not counted | 11 | 22 | −0.05 |
| Zeros counted | 8 | 24 | −0.03 |
| + haul cap + coverage | 4 | 20 | 0.02 |
| + spike filter | 3 | 20 | 0.05 |

The effect on the full pipeline is in 05 block 12.

## MEDIAS acoustic survey {#sec-medias}

Everything from @sec-fg-matching through @sec-regional describes **MEDITS**, the demersal trawl survey - but `01_biomass.R` (`AREA_MODE = "westmed"`) also incorporates **MEDIAS**, the acoustic survey, and combines the two into a single density index rather than keeping them as separate Ecopath/Ecosim sheets. MEDIAS is specifically relevant for small pelagics (sardine, anchovy) that a bottom trawl doesn't sample well but an acoustic survey does.

::: {.callout-important}
### MEDIAS is not part of the sample coverage map (@sec-area-definition)
MEDITS data arrives per-haul, with a real lat/lon for every sample - that's what @sec-area-definition's sample coverage map plots. MEDIAS data arrives **already aggregated** by country/GSA/year/species (no individual acoustic transect coordinates in the files this pipeline reads) - there's no per-point geometry to plot for it, so the coverage map only ever shows MEDITS. This isn't a bug or an oversight to fix; it's a structural difference in what the two source files actually contain.
:::

MEDIAS differs from MEDITS in several ways that matter for interpreting the combined result, not just in data source:

- **No strata weighting, no catchability correction.** @sec-strata-weighted and the catchability step in @sec-density don't apply here - there's no per-haul depth to stratify by, and MEDIAS' own acoustic backscatter-to-biomass conversion already accounts for detectability in a way a MEDITS-style catchability table doesn't map onto.
- **A fixed 10-200m depth band**, per the MEDIAS Handbook [@medias2025] - the acoustic sampling design's own minimum (10m isobath) and maximum (200m echo-sounding limit), not a modeling choice made in this pipeline.
- **Official reporting convention is t/nm²** (tons per square nautical mile), not the kg/km² MEDITS density work uses elsewhere in this pipeline - converted to t/km² before combining with MEDITS (`KM2_PER_NM2` conversion constant), so the two indices are on a comparable footing before averaging.

### Loading and FG matching

Raw abundance/biomass CSVs are collapsed to country/GSA/year/species (summing across length classes, replicate-checked to decide `sum()` vs `mean()` for collapsing raw records), then species codes are resolved to scientific names via the ASFIS species list (FAO's own code table) rather than MEDITS' own species-code system:

```{r}
#| label: medias-load-match
acoustic <- merge(acoustic_biom, acoustic_abund, by = c("country", "gsa", "year", "species"), all = TRUE)
acoustic <- merge(acoustic, fao_code_lookup, by = "species", all.x = TRUE)   # ASFIS Alpha3_Code -> ScientificName

acoustic_matched <- match_species_to_fg(acoustic[!is.na(ScientificName)], fg_lookup_safe)
acoustic_matched <- match_nominate_subspecies_fg(acoustic_matched, fg_lookup_safe)
acoustic_matched <- fallback_match_fg_by_taxonomy(acoustic_matched, fg_lookup_safe, taxonomy_source = "worms")
```

Once resolved to `ScientificName`, matching reuses the exact same `fg_lookup_safe` and the exact same Stage 1/1b/3 functions from @sec-fg-matching - a species matched here and a species matched in MEDITS go through identical logic, they just start from a different species-code system (ASFIS vs. MEDITS' own).

### Area denominator

MEDIAS density needs a country/GSA-level survey area (NM²), which - unlike MEDITS' bathymetry-derived stratum areas (@sec-strata-weighted) - primarily comes from each reporting institute's own published figure, the MEDIAS Handbook's Table 1:

### Combining MEDITS and MEDIAS into one index

Rather than write separate MEDIAS sheets, both surveys' FG-level and species-level density indices are stacked and **averaged** wherever they overlap on the same Year/FG (or Year/species) - this is the `species_density_regional_combined` object that everything from @sec-configure onward (`FG_spp_Ecopath`, `traits_ewe`, etc.) actually reads from, not MEDITS alone:

```{r}
#| label: medias-combine
fg_index_combined_raw <- rbindlist(list(
  fg_index_regional[, .(Year, FG_num, FG_name, mean_density, Survey = "MEDITS")],
  medias_fg_index_regional[, .(Year, FG_num, FG_name, mean_density = mean_density_biomass_t_km2, Survey = "MEDIAS")]
), fill = TRUE)

## FG/Year combinations present in BOTH surveys are flagged and printed,
## not silently averaged without comment - blending a demersal-trawl
## density with an acoustic density is a real methodological choice,
## worth a second look for the specific FGs/years it actually happens to
fg_overlap <- fg_index_combined_raw[, .N, by = .(Year, FG_num, FG_name)][N > 1]

fg_index_regional_combined <- fg_index_combined_raw[
  , .(mean_density = mean(mean_density, na.rm = TRUE)), by = .(Year, FG_num, FG_name)]
```

The species-level combination (`species_density_regional_combined`) follows the identical pattern - stack, flag genuine species/Year overlaps (typically a small pelagic taken in both an acoustic survey and incidentally in demersal trawl catches), then average.

::: {.callout-note}
### Averaging on overlap is a modeling choice, not a statistical inevitability
When both surveys report a density for the same FG (or species) and year, this pipeline takes a simple, unweighted mean of the two. An alternative - weighting by each survey's own sampling effort or estimated precision, rather than treating both estimates as equally trustworthy - would be a defensible different choice. The overlap is flagged and printed specifically so this default doesn't apply invisibly to combinations where the two surveys substantially disagree.
:::

This does more than plot points - it performs concrete geometric checks and reports them directly:

- **CRS is validated explicitly**, not assumed: `area_shp` and the sample points are both transformed to a common, known CRS before plotting rather than relying on automatic layer alignment, and the function errors clearly if `area_shp` has no CRS defined at all (rather than silently producing a badly misplaced polygon layer).
- **Points genuinely outside every polygon** (even after correct CRS alignment) are counted and listed - this distinguishes a real projection problem (should resolve to ~0 once fixed) from genuine bad coordinate data (stays nonzero regardless).
- **Points inside vs. outside the selected study area specifically** are shown in different colors - a point can be a perfectly valid coordinate in a real, neighboring GSA and still be outside this particular analysis's scope, which is a different question from "is this a valid coordinate at all".
- **The selected study area's outer contour** is drawn in bold, using a rasterize-then-repolygonize technique rather than a plain `st_union()` - real shapefiles are rarely perfectly topologically snapped at shared boundaries, and a plain union can leave a visible seam artifact at the join between adjacent polygons that a coarser raster grid smooths over.

## Biomass (`01_biomass.R` + `01b_biomass_unsurveyed.R`) {#sec-biomass}

`01_biomass.R` is the Step-1 script. It runs the survey method described above (MEDITS, plus MEDIAS when `AREA_MODE = "westmed"`) and then `source()`s `01b_biomass_unsurveyed.R` (`local = TRUE`) for every group a trawl or acoustic survey cannot measure. Together they write `Ecopath_B`, `FG_spp` and `Ecosim_ts`.

**Model area.** Every density in every sheet (biomass, catch, landings, discards) is expressed per km² of the same area:

$$
A_{model} = \sum_{g,h} A_{g,h} = 175{,}660\ \text{km}^2
$$

where $g$ is a GSA, $h$ a depth stratum and $A_{g,h}$ the stratum area (km²); here the MEDITS 10–800 m strata of GSAs 1, 2, 5, 6, 7, 8, 9, 10 and 11 (`strata_area_by_area.csv`, bathymetry from NOAA ETOPO via `marmap`; [@pante2013]). Habitats shallower than 10 m (most of the seagrass, lagoons) are outside this area by construction.

**Zeros in Ecosim series.** In `Ecosim_ts` a year with no catch in the survey, no recorded catch or no recorded discards is left blank, not 0: Ecosim fitting would read a 0 as an observed zero. `Ecopath_B` also carries `Biomass_1994_1996` (the value in `Biomass`) and the biomass of the first Ecosim year (`Biomass_1995`).

### Source priority per FG

First available wins, per FG × year:

1. A single-species stock assessment, for FGs the surveys do not measure (bluefin tuna, swordfish; `01b`, SOURCE A).
2. MEDIAS acoustic density (pelagic FGs; sardine and anchovy via the per-GSA series, eq. 9).
3. MEDITS density / $q$.
4. For FGs the surveys cannot sample (`EXEMPT_FG_NAMES`): the cited literature, habitat-map or plankton-model value from `01b` (SOURCES B–D). These are never back-filled with survey bycatch. If none exists the FG stays empty and is listed in `fg_missing_ecopath_B_REVIEW.csv`.

EcoBase biomass (other published Mediterranean EwE models; [@colleter2015]) is evaluated and written to `ecobase_biomass_evaluation_NOT_INCORPORATED.csv`, but never written into `Ecopath_B` (project decision).

### Stock assessments from the GFCM website

`STOCK_ASSESSMENT_SOURCE = "GFCM"` (default). GFCM publishes every validated Stock Assessment Form (SAF) [@gfcmsaf2026] as a PDF in a public folder (the files behind the "GFCM validated SAFs" browser on the GFCM stock assessment page). On each run `lib_gfcm_saf_online.R`:

1. lists all SAF PDFs and reads species (FAO 3-alpha code → ASFIS name), GSAs and reference year from the file names;
2. keeps stocks whose GSAs are all model GSAs, and downloads the newest SAF of each (cached in `data/fisheries/GFCM_SAF/pdf/`);
3. reads the summary results table: the table with a year column and an SSB column (else total biomass), from the word positions in the PDF; values in tonnes. If the newest SAF has no such table, the two previous SAFs of the stock are tried;
4. keeps a set of stocks that do not overlap: per species, the newest reference year, then the larger stock unit (hake GSAs 1-5-6-7 rather than hake GSA 1);
5. stocks with no readable table take the hand-transcribed `gfcm_saf_stock_assessments.csv`, then RAM Legacy when no GFCM stock of the same species overlaps (`GFCM_SAF_FILL_FROM_RAM`).

Output: `gfcm_saf_stock_assessments_ALL.csv` (column `use_for_biomass`) and `gfcm_saf_parse_REVIEW.csv` (per stock and SAF: status, page, column read, years). Offline, the last download is reused; with no earlier download the run falls back to RAM Legacy. `GFCM_SAF_UPDATE = FALSE` skips the online check.

::: {.callout-warning}
### Limits of the automatic reading
- Data-limited assessments (SPiCT, CMSY, survey-based advice) and most small-pelagic SAFs give biomass only in figures; those stocks get no GFCM value. In a test on the 73 newest SAFs inside GSAs 1–12 (October 2026), about 30 had a readable SSB table, most of them demersal (hake, red mullet, striped red mullet, deep-water rose shrimp, blue and red shrimp, giant red shrimp, Norway lobster, blue whiting, Moroccan sardine).
- A header that puts two quantities over one column is flagged "check: ambiguous header" and not used; a table that ends more than 2 years before the reference year is flagged too. Check `gfcm_saf_parse_REVIEW.csv` after each new download.
- SAF tables are in tonnes; a column labelled kg or thousand tonnes is converted.
:::

### European hake stanzas from the stock assessment

Hake is the only multi-stanza species. MEDITS catches mostly juveniles, so the stanza biomasses come from the hake stock assessments: by default the newest GFCM SAFs (GSAs 1-5-6-7 and the unit holding GSAs 9-11, GSAs 8-9-10-11 since 2023, from `gfcm_saf_stock_assessments_ALL.csv`); with `STOCK_ASSESSMENT_SOURCE = "RAM"` the STECF XSA assessments in RAM Legacy v4.44: GSA 1-5-6-7 (2003–2014), GSA 9-11 (2006–2014) and GSA 7 (1998–2012).

$$
B_{adult} \approx SSB, \qquad B_{juv} = B_{adult}\,\frac{1-r}{r}, \quad r = SSB/TB = 0.42
$$

where $SSB$ is the spawning stock biomass and $TB$ the total biomass of the assessment (both t, divided by $A_{model}$), and $r$ their ratio; $B_{adult}$ and $B_{juv}$ are the adult and juvenile stanza biomasses (t/km²). $B_{adult}$ is back-cast to 1994–1996 with the MEDITS hake index (× 0.84). Result on the 2026-10-22 run (whole-GSA area): adult (FG 27) 0.0246 t/km², juvenile (FG 26) 0.034 t/km². Ecosim: adult = the 17 assessment years (1998–2014), other years blank; juvenile = MEDITS index scaled to $B_{juv}$. Written to `hake_stanza_stock_assessment_REVIEW.csv`; parameters in `multistanza_reference_tables/hake_multistanza_parameters.csv`.

## Fisheries — Catches, Landings, Discards, Effort & F (`02_fisheries.R`) {#sec-fisheries}

`02_fisheries.R` builds the FG × year catch series, its landings/discards split by fleet (`Ecopath_L`, `Ecopath_Di`), the effort series, and the fishing mortality $F$ used by `03_pbqb-traits.R`.

### Catch domain

Only catch from the coastal states of the model GSAs is kept (`GSA_COASTAL_STATE`, from GFCM Res. GFCM/33/2009/2): `TARGET_COUNTRIES` = Spain, France, Italy, Morocco, Algeria and Tunisia for GSAs 1–12 (override with `TARGET_COUNTRIES_OVERRIDE`). Catch by countries with no coast in the model GSAs (distant-water fleets) is left out; the 02 log lists the excluded tonnes by country. STECF FDI is filtered to the model GSAs; the fleet register, gear table and FishMIP effort are filtered to the target countries.

### Equations

Indices: $c$ country, $f$ FG, $l$ fleet (country × fleet type), $y$ year.

1. Species → FG: $C_{c,f,y} = \sum_{s \in f} C_{c,s,y}$. FAO "NEI" groups are split over candidate FGs in proportion to biomass, with an $F \le 1$ cap (below). "Marine molluscs nei" (3,814 t/yr in 1994–1996) is split over the commercial mollusc FGs in proportion to the mollusc catch the same country reported to species or group level in the same year, $C_{nei,f,c,y} = C_{nei,c,y}\,C_{id,f,c,y}/\sum_f C_{id,f,c,y}$ (fallback: the country's all-year shares, then all countries pooled; `mollusc_nei_split_by_country_year.csv`). In 1994–1996 the identified mollusc catch was about 44 % cephalopods and 56 % bivalves/gastropods.
2. Catch source (`CATCH_FDI_FIRST`): for Spain, France and Italy the STECF FDI landings of the model GSAs are used directly in every Country × FG × year FDI reports (2014+); GFCM is used for the years before FDI (incl. 1994–1996) and for Morocco, Algeria and Tunisia. The pre-FDI GFCM years are scaled to the FDI level, $k_{c,f} = \sum C^{FDI} / \sum C^{GFCM}$ over 2014–2023, so the series has no step at 2014; factors > `MAX_CATCH_CALIBRATION_FACTOR` (10) are not applied (`catch_calibration_factor_capped_REVIEW.csv`).
3. Gears with no model fleet (`FleetType = EXCLUDED`): $C \leftarrow C\,(1 - \text{share}_{excl,c,y})$, share from FDI (2014+) or SAU (earlier). The removed tonnes are in the 02 log.
4. Discards: $Di = C \times r$, $r$ = FDI per-fleet discard ratio, else the FishMIP reported-vs-total ratio by FG × year; $L = C - Di$.
5. ICCAT (bluefin tuna, swordfish, albacore): Task I nominal catch of the target countries, Mediterranean records only, scaled to the model GSAs by each country's FDI landings share inside them: $C^{ICCAT}_{c,sp} \times s_{c,sp}$. Shares in this run: Italy SWO 0.59, BFT 0.57, ALB 0.23; Spain BFT 0.95, SWO 0.89; France 1.
6. Fleet split: $C_l = C_{c,f,y}\,p_{l,c,f,y}$; $p$ from FDI (2014+), SAU hindcast bias-corrected to FDI (earlier), else FDI multi-year mean, else country mix, else equal share (flagged). Target-country catch whose fleet cannot be resolved goes to the residual column "Target countries - fleet not resolved" (renamed on 2026-10-07; it no longer holds other countries' catch).
7. Hake stanzas: juvenile share of the catch from MEDITS length frequencies (TC, 1994–1996, model GSAs), $L(a) = L_\infty(1 - e^{-K(a - t_0)})$ with $L_\infty$ = 110 cm, $K$ = 0.178 yr⁻¹, $t_0$ = 0 [@mellonduval2010], $W = aL^{3.035}$; juvenile = age < 2 yr ($L$ < 32.9 cm); landings are $L \ge$ MCRS 20 cm [@reg1967_2006; @reg2019_1022]. Result: 55.9 % of landings and 100 % of discards are juvenile (FG 26), applied at fleet level too.
8. Effort (EU): $E_{l,y} = NE_{c,y}\,\kappa_c\,s_{l,y}$, $NE$ = Rousseau et al. nominal effort, $\kappa_c = \sum E^{FDI}/\sum NE$ over the overlap years. With `EFFORT_PRIMARY_SOURCE = "rousseau"` (default) this one formula is used for **every** year, so the series has no source change at 2014. FDI is used only for $\kappa_c$, for the days-per-tonne used in the fleet share $s_{l,y}$ (catch × days-per-tonne share, rescaled per fleet to the 2014–2016 FDI mean), and to carry the trend after Rousseau's last year: $E_y = E_{last}\,E^{FDI}_y / E^{FDI}_{last}$. FDI's own effort is kept as a check column (2014 Rousseau-based / FDI ratio ≈ 1.14 for France in this run). Before this change, stitching the hindcast to FDI at 2014 gave jumps of up to ×196.
9. Technology creep (effective effort), compounded year by year from the base year $t_0$ = 2014 (first FDI year): $E'_t = E_t \prod_{y=t_0+1}^{t}\left(1 + \frac{m_c\,m_s\,r_{g,y}}{100}\right)$ for $t > t_0$ and $E'_t = E_t \big/ \prod_{y=t}^{t_0-1}\left(1 + \frac{m_c\,m_s\,r_{g,y}}{100}\right)$ for $t < t_0$; $E$ = nominal effort in kW × fishing days (FDI total over vessels, = mean kW × mean days × number of vessels; [@rousseau2024] nominal active effort), $r_{g,y}$ = annual creep rate (%) of gear $g$ in year $y$, $m_c$ = country multiplier (EU 1, Morocco/Algeria/Tunisia 0.7, ASSUMPTION), $m_s$ = sector multiplier. Creep is applied to the whole series, including the non-EU years after 2017 where the nominal effort is held at its 2017 value, so effective effort keeps rising. Ecosim uses effort relative to 1995, so the choice of $t_0$ changes the level but not the trend. Rates: $r$ = 0.79 %/yr bottom trawl and 2.0 %/yr other gears in 1994–2013 ([@damalas2015], quoted by [@tsagarakis2022]), 4.5 %/yr in 2014–2023 ([@palomares2019], $C\% = 13.8\,Y^{-0.511}$ at $Y$ = 9). Sector multiplier: industrial 1.0, artisanal/recreational 0.6 (ASSUMPTION).
10. Ecopath: $L_{f,l} = \overline{L}_{y \in 1994\text{–}1996} / A_{model}$ (t/km²/yr, same $A_{model}$ as biomass).
11. **Fishing mortality**: $F_f = (\bar C_f / A_{model}) / B_f$, with $B_f$ = the final `Ecopath_B` written by `01_biomass.R` (survey species density only for FGs without an Ecopath_B). Using the final Ecopath_B (not the survey density) keeps F consistent for groups whose biomass comes from `01b` (macrozooplankton, suprabenthos) and gives adult hake (FG 27) an F. The same $B_f$ is used by the NEI $F \le 1$ cap.
12. Ecosim: catch series $C_{f,y}/A_{model}$; effort series relative to 1995.

## PB/QB & Life-History Traits (`03_pbqb-traits.R` + `03b_ecobase.R`) {#sec-pbqb-traits}

`03_pbqb-traits.R` computes P/B and Q/B per species by taxon group and aggregates them to FGs, weighted by biomass. Life-history data come from FishBase [@fishbase] and SeaLifeBase [@sealifebase] via `rfishbase` [@boettiger2012]. `03b_ecobase.R` supplies EcoBase values as a cross-check and gap-filler only. Equation numbers refer to the project protocol "Quick guide on how to calculate P/B and Q/B for EwE models".

### Equations

| Group | P/B | Q/B |
|---|---|---|
| Fish | $P/B = Z = M + F$ [@allen1971]. $M$ priority: [@then2015] > [@pauly1980] ($\log_{10} M = -0.0066 - 0.279\log_{10}L_\infty + 0.6543\log_{10}K + 0.4634\log_{10}T$) > [@hoenig1983] > [@alverson1975] (via TropFishR; [@mildenberger2017]) > FishLife [@thorson2017] > [@gascuel2008] ($M = 2.31\,TL^{-1.72}e^{0.053T}$). $F$ from 02 (@sec-fisheries). | [@palomares1998]: $\log_{10} Q/B = 5.847 + 0.280\log_{10}Z - 0.152\log_{10}W_\infty - 1.360\,T' + 0.062A + 0.510h + 0.390d$, $T' = 1000/(T+273.15)$; no-$Z$ variant; [@christensen1992]; Q/P = 3 fallback |
| Marine mammals | Siler survivorship [@barlow1991], else $20.19\,TL^{-3.26}e^{0.041T}$ [@gascuel2008] | $365 \times 0.1\,W^{0.8}/W$ [@innes1987; @trites1997], $W$ = mean body mass in kg (`homeotherm_mean_body_mass.csv`: [@carlucci2024], to be completed from [@tritespauly1998]; else FishBase/SeaLifeBase maximum mass, flagged) |
| Seabirds | [@gascuel2008] | $365 \times 10^{-0.293 + 0.85\log_{10}W}/W$ [@nilsson1976], $W$ = mean body mass in g (to be completed from [@dunning2008]; else maximum mass, flagged) |
| Invertebrates | [@tumbiolo1994]: $\log_{10}P = 0.24 + 0.96\log_{10}B - 0.21\log_{10}W_{max} + 0.03T - 0.16\log_{10}(z+1)$; [@brey1999] ($M_{max}$ at 4.5 kJ/g, ASSUMPTION); [@gascuel2008] fallback | $Q/B = 3\,P/B$ [@christensen2008] |
| Primary producers | — | $Q/B = 0$ |

FG level: $X_f = \sum_s B_s X_s / \sum_s B_s$. Missing species values are borrowed from the closest relative (genus > family > order > class).

**Fishing mortality for non-fish FGs.** $P/B = Z = M + F$ [@allen1971] holds for every group, not only fish, as long as the empirical P/B is natural mortality. Fish species get $P/B = M + F$ inside `calc_fish()`. For invertebrate, mammal and seabird FGs the FG-level $F$ from `02_fisheries.R` (`F_by_fg.csv`) is added to the part of the FG whose P/B is natural mortality (Siler survivorship; Tumbiolo & Downing; Brey), $P/B_f = P/B^{emp}_f + F_f\,(1 - s_f)$, where $s_f$ is the biomass share of the FG whose P/B comes from the [@gascuel2008] equation: that equation was fitted to the P/B of published EwE models, i.e. total mortality, so it already includes fishing (all seabirds, and the fallback for mammals and invertebrates); and for invertebrates $Q/B_f = 3\,P/B_f$ is computed on that P/B, so a fished group's P/B includes its fishing mortality (otherwise Ecopath cannot balance it, e.g. coastal benthic cephalopods with $F$ = 0.85). ASSUMPTION: the empirical invertebrate P/B is treated as natural mortality.

::: {.callout-warning}
### Known caveats
- The fish Q/B diet-type dummies ($h$, $d$) are fixed defaults, not taken from a diet classification.
- `QB_InnesTrites_1987_1997` and `QB_NilssonNilsson_1976` are conventionally cited, not re-verified against the primary papers.
- 28 of 68 FGs fall outside the 0.05–0.3 P/Q range; 8 FGs have no P/B or Q/B (3 Expanding FGs, corals and gorgonians, meso and micro zooplankton, Cymodocea, detritus, discards).
- 23 FGs differ from the EcoBase average by more than 2× (mostly cephalopods, decapods, macrobenthos, suprabenthos, where the empirical value is lower).
:::

## Diet Matrix (`04_diets.R`) {#sec-diets}

`04_diets.R` builds the predator FG × prey FG diet matrix ($DC_{f,j}$, columns sum to 1; [@christensen2005]). It sources `lib_fishbase_diet_matrix.R` and `lib_worms_taxonomy_lookup.R`.

### Tiers (first available per predator FG)

1. **Mediterranean trophic metaweb** [@collmetaweb] (`data_entry_metaweb_empty.xlsx`, `DATA_ENTRY`; codes resolved through its `Taxonomic_codes` and `Non_taxonomic_groups` tabs). One metric per study (study = reference × area × years × life stage × season), chosen by `diet_metric_priority.csv` (IRI [@pinkas1971] > %W > %Vol > stable-isotope mixing model > %N > %F > presence; [@hyslop1980]), normalised to 1. Since 2026-10-14 the rows go through the same prey → FG resolution, stage selection and biomass weighting as MAISHA and FishBase (`metaweb_diet_records()`); generic metaweb groups ("Pelagic fish", "Zooplankton", "Pelagic tunicates", ...) are placed by rules at the top of `fishbase_food_category_to_fg.csv`. The choice is made **per predator FG**: an FG with any metaweb record takes its diet only from the metaweb; FGs without one take it from tiers 2–4. The template is still empty, so for now every FG comes from tiers 2–4.
2. **MAISHA** ([@vascotto2026], v1.2, OGS NODC, doi:10.13120/hwpn1e, CC-BY 4.0): Darwin Core Archive (`data/diet/MAISHA/MAISHA_DwC-A`); predator records (`occurrenceRemarks == "Predator"`) linked to prey through `associatedOccurrences`; gravimetric %, then numerical %, then frequency of occurrence from the extended measurement table; detritus kept as a prey item, unknown and debris dropped; studies tagged as Mediterranean by coordinates (lon −6 to 36.5, lat 30 to 46), and non-Mediterranean studies dropped for a predator that has Mediterranean ones.
3. **FishBase / SeaLifeBase** diet tables [@fishbase; @sealifebase] (DIET, DIETITEMS, FOODITEMS), Mediterranean studies first; DietCode joins done per server because FishBase and SeaLifeBase codes collide.
4. **EcoBase** diet matrices [@colleter2015] — the public web service exposes none, so this tier currently finds nothing.

MAISHA and FishBase records are pooled per predator species and studies are averaged with equal weight.

**Two matrices.** The *main* matrix (`Ecopath_diet`) follows the tiers above. A *reference* matrix (MAISHA, then FishBase/SeaLifeBase for species without MAISHA records) is built for **every** predator FG, whether or not the metaweb covers it. `diet/diet_matrix_main_vs_reference.xlsx` puts them side by side (sheets Main, Reference, Main_minus_Reference, Source; long form in `diet_main_vs_reference_REVIEW.csv`), so single values of the main matrix can be checked and tuned by hand against an independent estimate. After a hand change, the column must sum to 1 again.

### Prey → FG and aggregation

$$
p_{s,d,k} = v_k / \textstyle\sum_k v_k, \qquad DC_{s,j} = \frac{1}{n_s}\sum_d\sum_k p_{s,d,k}\,w_{k\to j}, \qquad DC_{f,j} = \frac{\sum_{s \in f} b_{s|f}\,DC_{s,j}}{\sum_{s \in f} b_{s|f}}
$$

Here $s$ is a predator species, $d$ one diet study of that species ($n_s$ studies in total), $k$ a prey item in that study with value $v_k$ (% weight, volume or frequency as reported), $p_{s,d,k}$ its share within the study, $j$ a prey FG, $DC_{s,j}$ the fraction of FG $j$ in the diet of species $s$, $f$ the predator FG and $DC_{f,j}$ its diet composition. $w_{k \to j}$ is the share of prey item $k$ assigned to FG $j$: prey species in `FG_WMed_2026.csv` → its FG; else the genus, family, order, class or phylum shared with model species → equal split over the FGs holding that taxon (`DIET_TAXON_SPLIT`); else a food-category rule (`diet_reference_tables/fishbase_food_category_to_fg.csv`, about 44 regex rules) → split by Ecopath B of the target FGs (`DIET_CATEGORY_SPLIT`, ASSUMPTION: prey taken in proportion to availability); else a second pass resolves the prey name through WoRMS and repeats the rank match (cache `diet/worms_diet_prey_cache.rds`). Fish eggs and larvae go to zooplankton. Detritus/debris items are dropped for predators with FishBase trophic level ≥ 3 (`DIET_DETRITUS_MAX_TL`, ASSUMPTION: digested remains, not detritus feeding). Non-food items are dropped and the study renormalised. $b_{s|f}$ = species share of FG biomass (`biomass_proportion_by_species_fg.csv` from 01).

### Coverage of the diet sources

- MAISHA: 496 predator records (417 inside the Mediterranean box), 9,801 prey records → 54 predator FGs, 230 species, 426 study records.
- FishBase/SeaLifeBase: 48 predator FGs, 262 species, 389 study records (DIET 272, DIETITEMS 1,499, FOODITEMS 3,892 rows pulled for 1,084 species, cached).
- Combined: 70 predator FGs, 492 species, 815 study records. Provenance: MAISHA + FishBase 54 FGs, FishBase/SeaLifeBase only 16, missing 3 (corals and gorgonians, meso and micro zooplankton, suprabenthos). 70 of 80 FGs have at least one cited diet study.
- All predator columns sum to 1. Cannibalism above 0.1: jellyfish 0.497, other macro-benthos 0.156, benthic mollusc 0.114.
- Unassigned prey item types: 58 (`*_unassigned_items_REVIEW.csv`).
- Technical note: on a pCloud drive, files that are not fully downloaded can crash `data.table::fread` (memory-mapping error, "R bomb"). `lib_fishbase_diet_matrix.R` therefore copies the MAISHA files and cached FishBase tables to a local temporary file before reading them (`.fread_local()`).

Outputs: `diet/Metaweb/`, `diet/MAISHA/` and `diet/FishBase/` (each source alone), `diet/reference_diet_matrix_fg_long.csv` / `_wide.csv` (reference matrix, all FGs), `diet/diet_matrix_main_vs_reference.xlsx` and `diet_main_vs_reference_REVIEW.csv`, `diet_provenance_by_predator_fg.csv`, `diet_references_by_fg.csv`, `diet_composition_ewe.csv` (EwE import format).

## Validation (`05_validation.R`) {#sec-validation}

`05_validation.R` reads what 01–04 wrote; it does not change any input sheet.

### STEP A — comparison with the 1995 Western Mediterranean model

Reference: the "estimates" sheet of `WMed_EwE.xlsx` [@wmed1995model], model area $A_{old}$ = 846,002 km². Old groups are matched to new FGs through `validation_reference_tables/old_to_new_fg_crosswalk.csv` (33 rows): several old groups → one new FG are summed (P/B and Q/B biomass-weighted); one old group → several new FGs is compared with the sum of the new FGs.

$$
\text{ratio} = X_{new}/X_{old}, \qquad X_{old}^{(A_{new})} = X_{old}\,A_{old}/A_{new}, \qquad \text{ratio}_{same\ total} = X_{new}/X_{old}^{(A_{new})}
$$

where $X$ is B (t/km²), P/B or Q/B (1/year) of an FG, $X_{new}$ this model's value, $X_{old}$ the 1995 value and $A_{new}$, $A_{old}$ the two model areas (km²); the area rescaling applies to B only. The second form compares the same total tonnes. Flags: ratio outside `VALIDATION_RATIO_LOW`–`VALIDATION_RATIO_HIGH` (0.5–2), values appearing/disappearing. In a recent full run about half of the FG × metric rows were flagged (a review prompt, not a verdict). The old sheet has no landings/discards columns, so only B, P/B and Q/B are compared.

### F vs P/Q check (`03_pbqb-traits.R`)

Because $P/B = M + F$, a large $F$ raises P/B and P/Q. For every FG with $F > 0$, `F_vs_PQ_diagnostic_REVIEW.csv` gives $F$, P/B, the part without fishing ($P/B - F$), $E = F/Z$, P/Q with and without $F$, catch and B, and flags: $F > 1$; $F$ alone pushes P/Q above 0.3; $E > 0.5$ [@gulland1971]. A flagged FG points to too much catch assigned to it or too little B. Invertebrates have Q/B = 3 P/B, so their P/Q is 0.33 by construction. On the 2026-10-13 data: 14 FGs flagged, 7 with $F > 1$, and $F$ pushes P/Q above 0.3 only for groupers (0.52) and bluefin tuna (0.32).

### STEP B — consolidated checks

`validation_summary_ALL.csv` indexes every REVIEW file of 01–04: P/B, Q/B and GE plausibility; P/Q outside 0.05–0.3; diet column sums ≠ 1; cannibalism > 0.1 (EwE User Guide); missing diets; EcoBase evaluations; FGs without Ecopath_B; even species splits; temporal mismatches; fleet coverage; zero-catch FGs; unmatched old FG names.

Three more checks are written by `05_validation.R` itself and added to the same summary:

- **Fishing mortality above 1** (`F_above_1_REVIEW.csv`): FGs with $F = (C/A_{model})/B > 1$ in the Ecopath years, from `F_by_fg.csv`.
- **Time series assessment** (`ecosim_ts_assessment_REVIEW.csv`, plot 13): for each Ecosim_ts series, the years with data, first and last year, longest gap, $CV = sd/\bar{x}$ and the largest year-to-year jump $\max(x_t/x_{t-1},\ x_{t-1}/x_t)$. Flags: fewer than 5 years, gap > 5 years, CV > 1, jump > 5×.
- **Unsurveyed FGs vs other models** (`unsurveyed_fg_vs_other_models_REVIEW.csv`, plot 14): this model's B next to other Mediterranean EwE models listed in `validation_reference_tables/unsurveyed_fg_other_models.csv`, each with its own area (a small coastal model has much more seagrass per km²). Flag: other value more than 10× or less than 0.1× ours. Add rows to that table as you find models.

The models compared so far are the 1995 Western Mediterranean model [@wmed1995model], the Gulf of Lion model [@seyer2023] and the Port-Cros model [@valls2009; @valls2012].

### Outlier removal effect (from `01_biomass.R`)

### PREBAL — biomass, P/B and Q/B against trophic level

Before balancing, log biomass and log vital rates should decline steadily with trophic level, with no group far off the line [@link2010; @heymans2016]. The trophic level of each FG is computed from the `Ecopath_diet` sheet:

$$
TL_i = 1 + \sum_j DC_{ij}\, TL_j
$$

where $DC_{ij}$ is the fraction of prey $j$ in the diet of predator $i$ (each diet column rescaled to sum to 1), and $TL_j = 1$ for primary producers, detritus and any FG with an empty diet column. It is solved by iteration until no TL changes by more than $10^{-6}$. For each metric $X \in \{B, P/B, Q/B\}$ the pipeline fits

$$
\log_{10} X_i = a + b\, TL_i + \varepsilon_i
$$

and reports the change per trophic level, $100\,(10^{b} - 1)$ %, in `prebal_slopes.csv`. An FG is flagged in `prebal_REVIEW.csv` when $|\varepsilon_i| > 2\,s_\varepsilon$ ($s_\varepsilon$ = standard deviation of the residuals of that metric). Detritus and discards are excluded.

Link (2010) suggests biomass should fall by roughly 5–10 % per TL on the log scale over the whole web; a much steeper slope points to under-estimated top predators or over-estimated low TLs. On the 2026-10-22 run: B −82 % per TL, P/B −55 % per TL, Q/B +5 % per TL. The Q/B slope is flat because the two seabird FGs have Q/B ≈ 72 /year (flagged). Groups with TL = 1 besides producers (corals and gorgonians, meso/micro zooplankton, suprabenthos) have no diet column yet, so their TL is a placeholder — check the diet matrix for them.

### Data pedigree

Each input of each FG gets a pedigree index from 0 (no data, estimated by Ecopath) to 1 (local, high-precision data), following the EwE pedigree categories [@christensen2004; @christensen2008]. The source is read from the workbook and matched to a category by the rules below (first match wins; edit `PEDIGREE_RULES`, or point `PEDIGREE_RULES_FILE` to a CSV with columns `input, pattern, index, category`).

| Input | Source in the workbook | Category | Index |
|---|---|---|---|
| B | Biomass left blank (EE fixed) or placeholder | Estimated by Ecopath / guesstimate | 0.0 |
| B | ISIMIP ocean model (plankton) | From other model | 0.0 |
| B | Megafauna sighting density × body mass; habitat cover × site density | Approximate or indirect method | 0.4 |
| B | MEDITS trawl, MEDIAS / acoustic series, stock assessment | Sampling-based, low precision | 0.7 |
| P/B, Q/B | EcoBase (other Mediterranean EwE models) | From other model | 0.2 |
| P/B, Q/B | Empirical equation (e.g. Tumbiolo & Downing, Palomares & Pauly) | Empirical relationship | 0.5 |
| P/B, Q/B | Published estimates for the same species | Same species, similar system | 0.8 |
| Diet | No diet | General knowledge / no data | 0.0 |
| Diet | FishBase FOODITEMS (prey presence only) | Qualitative | 0.2 |
| Diet | FishBase DIETITEMS (quantitative, other areas) | Quantitative, other systems | 0.5 |
| Diet | MAISHA, 1–4 Mediterranean studies | Quantitative but limited | 0.7 |
| Diet | MAISHA, ≥ 5 Mediterranean studies | Quantitative, detailed | 1.0 |
| Catch | FDI / GFCM landings | National statistics | 0.7 |

MEDITS biomass is classed as low precision because it depends on an assumed catchability and on the swept-area expansion (ASSUMPTION; it could be argued up to 1.0 for well-sampled demersal fish). The overall index is

$$
P = \frac{1}{n}\sum_{i=1}^{n} \frac{1}{J_i}\sum_{j=1}^{J_i} I_{ij}
$$

where $I_{ij}$ is the index of input $j$ for FG $i$, $J_i$ the number of inputs with an index for FG $i$ and $n$ the number of FGs. On the 2026-10-22 run, $P \approx 0.65$. Results per FG are in `pedigree_REVIEW.csv`; the summary row counts sources not matched by any rule plus inputs with index < 0.3.

### Zooplankton field check (block 11)

Field reference: [@fernandez2023] — RADMED, Alborán to Balearic Sea, 2007–2017, Bongo 250 µm, daytime oblique tows 0–100 m: total zooplankton 2–17 mg DM/m³ (mean ≈ 10).

$$
z_{eff} = \frac{\sum_k A_k \min(z^{mid}_k, 100)}{\sum_k A_k} = 86.7\ \text{m}, \qquad B_{tot} = \frac{DM \times z_{eff}}{DW{:}WW \times 1000}
$$

where $k$ is a depth stratum, $A_k$ its area (km²), $z^{mid}_k$ its mid-depth (m, capped at the 100 m tow depth), $z_{eff}$ the area-weighted sampled depth, $DM$ the field zooplankton concentration (mg dry mass/m³), $DW{:}WW$ the dry-to-wet weight ratio and $B_{tot}$ the total zooplankton biomass (t WW/km²: $DM \times z_{eff}$ is in mg DW/m², and 1 mg/m² = 0.001 t/km², hence the 1000). DW:WW 0.1–0.2 (ASSUMPTION). Salp upper bound: $DM \times z_{eff} / 0.0804 / 1000$ (salp DW:WW 0.0804, *Thalia democratica*, Add-my-Pet). Result: field 0.87–15 t/km² (mean 5.8); model FGs 68 + 69 + 71 + 72 ≈ 33 t/km² (meso + micro at the COBALT level, 29.6, + macro 3.15); salp bound 10.8 t/km². The net misses most microzooplankton, so the model total should sit above the field value.
