Purpose of this document

This document describes a general-purpose R pipeline for turning MEDITS/ MEDIAS trawl-survey and catch data into input sheets for an Ecopath-with- Ecosim (EwE) model, for any region in the Mediterranean Sea — a single GFCM Geographical Sub-Area (GSA), any subset or the full set of GSAs, or a completely user-defined region (a bounding box or an arbitrary shapefile that doesn’t line up with GSA lines at all, e.g. a bay, an MPA, or a footprint spanning parts of several GSAs). It covers every script provided, what each one reads and writes, and every function in the shared library those scripts call.

The scripts as delivered are configured for the Western Mediterranean (GSA 1–11) as a worked example — this is what 01_biomass.R, export_gsa_boundaries.R and fig_WMed_basemap.R currently point at, and what a few reference tables (e.g. the MEDIAS Handbook area crosswalk) are currently populated for. The underlying mechanism — GSA-based selection via FILTER_AREAS, or an arbitrary region via 01_survey_density_custom.R — is not Western-Med-specific; see Adapting this pipeline to a different region below for exactly what to change to point the same pipeline at another part of the Mediterranean.

All scripts read from and write to one shared workbook, output/ecopath_ecosim_inputs.xlsx, via two library functions designed for exactly this purpose:

  • upsert_workbook_sheets() — adds/replaces named sheets, leaves every other sheet in the workbook untouched. Safe to call from any script, in any order, any number of times.
  • finalize_workbook_sheet_order() — run last, after every upstream script has run at least once. Renames a couple of sheets (FG_lookup → FG, References → PB_QB_References_) and reorders every sheet into the final layout Ecopath/Ecosim expects.

Because of this design, the four numbered pipeline scripts are order-independent with respect to the shared workbook — except where a script’s own calculations literally need a file another script produced first (documented per-script below).

Script 1a — 01_biomass.R

Role: Pipeline Step 1 of 4, GFCM-GSA-based version — the general mechanism for any GSA subset anywhere in the Mediterranean, not just the Western Med. Run this or 01_survey_density_custom.R, not both, as Step 1. No dependency on the other numbered scripts; 02_fao_catches.R and 03_pbqb-traits.R both require this step’s output to exist first.

Runs two independent surveys over the same GSAs/FG scheme (MEDITS bottom trawl + MEDIAS acoustic) and combines both into one set of Ecopath/Ecosim sheets, rather than producing separate MEDIAS sheets. As delivered it’s configured for the Western Med (GSA 1–11, via FILTER_AREAS <- 1:11) as a worked example; retargeting it to a different GSA subset elsewhere in the Mediterranean — the Adriatic, the Aegean, the whole basin — is a matter of changing that one line and the region-specific reference tables listed in Adapting this pipeline to a different region.

Step 7b — AquaMaps shallow/deep depth adjustment (opt-in)

MEDITS’ own 5 standard strata (MEDITS_STRATA) only cover 10–800 m. compute_strata_area_by_area()’s area-proportion weighting normalizes across just those 5 strata, so as delivered, this pipeline’s Biomass/ density figures implicitly treat the whole modeled area as if it were entirely 10–800 m seafloor — a species with real biomass shallower than 10 m or deeper than 800 m is invisible to these numbers, not just imprecisely measured. Setting APPLY_AQUAMAPS_DEPTH_ADJUSTMENT <- TRUE (default FALSE) adds genuine derived pseudo-strata: one shallow (0–10 m) plus, by default, the deep zone split into two sub-bands — 800–1000 m and 1000–2850 m — rather than one lumped 800–6000 m stratum (2850 m is a practical ceiling for the western Mediterranean’s own real depths specifically, not the Mediterranean-wide ~5267 m Calypso Deep, which sits in the eastern/Ionian basin outside these GSAs). Each pseudo-stratum gets its own real bathymetric area (the same compute_strata_area_by_area() machinery already used for the 5 real strata) and a density derived, not measured, anchored to the ONE real MEDITS stratum immediately adjacent to it — the shallowest real stratum (10–50 m) for the shallow pseudo-band, the deepest real stratum (500–800 m) for every deep pseudo-band — rather than an area-weighted average across all 5 real strata. Each pseudo-stratum’s density equals that adjacent stratum’s own measured density (compute_species_ anchor_stratum_density()), scaled by the ratio of AquaMaps mean suitability between the pseudo-band and that same adjacent stratum’s own depth range. A species at equal AquaMaps suitability in both bands gets a multiplier of exactly 1 — its pseudo-stratum density literally equals what MEDITS measured next door, with no distortion from averaging across strata the species may barely occupy. (An earlier version of this adjustment compared each pseudo-band’s suitability against the whole 10–800 m composite range instead — that systematically understated narrow pseudo-bands relative to the ~790 m-wide reference purely from the width mismatch, independent of actual suitability level; the anchor-stratum design replaces it.) The trade-off: a species with real catch elsewhere in 10–800 m but none specifically in the one adjacent anchor stratum gets no pseudo-stratum density at all for that area (flagged in the audit sheet), rather than being extrapolated from unrelated, non-adjacent strata. These pseudo-strata are folded into the exact same weight_by_strata()/weight_species_by_area() calls used for the 5 real strata — not a separate formula — so fg_index/ fg_index_regional/species_density_regional end up as one consistent area-weighted sum across all 8 strata (5 real + 3 derived), real and derived alike. The number and boundaries of deep sub-bands are controlled by apply_aquamaps_depth_adjustment()’s deep_ranges argument — a list of c(from, to) pairs — so this can be collapsed back to one lump (list(c(800, 6000))) or split further without changing anything else; all deep sub-bands anchor to the same deepest real stratum, they don’t chain off each other.

Core assumption, stated plainly rather than absorbed silently: a species’ relative density across depth is assumed proportional to AquaMaps’ relative occurrence-suitability across depth (its trapezoidal DepthMin/DepthPrefMin/DepthPrefMax/DepthMax envelope, per AquaMaps’ own “Algorithm and Data Sources” documentation). Occurrence suitability is not the same thing as density — this is a standard extrapolation approach when direct sampling doesn’t cover a species’ full depth range, but an approximation nonetheless. Every resulting multiplier is written to the AquaMaps_Depth_Adjustment sheet (species, its DepthMin/DepthPrefMin/DepthPrefMax/DepthMax, probability masses, resulting multiplier_shallow/multiplier_deep_800_1000/ multiplier_deep_1000_2850 (one column per configured deep sub-band, named by its own depth bounds), and a note explaining species that got NO adjustment for a given band — unmatched to AquaMaps, no depth envelope in am_hspen(), or essentially zero AquaMaps suitability in that band’s own adjacent real anchor stratum, making a ratio against that unstable) — reviewable per species, not a black box.

Requires the aquamapsdata R package (github.com/raquamaps/aquamapsdata), the only verified way to get AquaMaps’ per-species HSPEN depth-envelope table without scraping — its download_db() pulls a real, deliberate ~2GB (~10GB unpacked) local SQLite database once (ensure_aquamaps_db() uses force = FALSE, so this never re-downloads on subsequent runs). Implemented in lib_aquamaps_depth_extension.R (species → AquaMaps SpeciesID resolution, envelope fetch, envelope math, pseudo-strata construction) — see that file’s own header for the full mechanism. Requires STRATA <- TRUE (errors clearly if not — there’s no unstratified equivalent). Not yet wired into 01_survey_density_custom.R — only 01_biomass.R has this option so far.

Two outputs make the strata (real + derived) inspectable directly, independent of APPLY_AQUAMAPS_DEPTH_ADJUSTMENT — they cover whichever strata are actually in play, 5 or 8:

  • survey_fg_depth_strata_profile.png (Step 8, plot_strata_profile()) — a bar chart of raw per-sample density by stratum, faceted per FG, for sanity-checking that known deep-water FGs actually peak in the deep strata and vice versa. Reads weight_by_strata()’s per_stratum_raw attribute specifically (not per_stratum), so a stratum with real sample data but no computed area-proportion for a given AreaID still shows up here rather than silently vanishing.
  • FG_Density_by_Stratum sheet (Step 12c, build_fg_density_by_stratum_sheet()) — the same information as an Excel table: one row per FG, one column per stratum (region-wide, area-weighted, YEAR_ECOPATH-averaged), plus a Total_Density column that reproduces fg_index_regional’s own mean_density exactly, since each stratum column is that stratum’s own additive contribution to the total, not an independently-normalized figure.

Processing steps

  1. Config — resolve out_dir/pcloud_dir/git_dir, download/cache the GSA shapefile, source lib_survey_fg_density_functions.R and lib_worms_taxonomy_lookup.R.

  2. Load MEDITS data — read TA.csv/TB.csv, compute swept area (distance × wing_opening_m / 1e6, wing opening in decimetres), convert DDMM.mmm lat/lon to decimal degrees, fix the Alboran Sea (GSA 1–3) longitude sign — a Western-Med-specific correction, harmless (a no-op) if your FILTER_AREAS doesn’t include GSA 1–3 — reshape into the standardized dataframe1/dataframe2 format. Runs validate_survey_data() and plot_sample_map() (→ survey_sample_coverage_map.png, survey_sample_coverage_map_by_year.png).

  3. FG matching (Steps 3–4) — prepare_fg_lookup() → match_species_to_fg() → match_nominate_subspecies_fg() → manual overrides (species codes absent from the MEDITS taxonomic list, e.g. ARGRACU→Argyropelecus aculeatus) → fallback_match_fg_by_taxonomy() (Genus→Family→Order→Class→Phylum) → apply_seed_fg_rules() (FGs with zero reference species, e.g. Holothuroidea→“Sea cucumbers”) → summarize_unresolved_species() → survey_unmatched_for_manual_review.csv.

  4. Densities (Step 5) — match_samples_to_area(), assign_depth_stratum(), compute_sample_densities(), restrict to FILTER_AREAS, apply_catchability_correction() (if the catchability CSV exists), remove_sample_outliers() (→ survey_outliers_flagged.csv if any flagged), compute_fg_densities_by_stratum().

  5. Strata/area weighting (Steps 6–7) — compute_strata_area_by_area() (cached to strata_area_by_area.csv), weight_by_strata(), weight_by_area(), compute_species_densities_by_stratum(), weight_species_by_area().

  6. MEDITS plots (Step 8) — plot_fg_timeseries_by_area(), plot_fg_timeseries_regional(), plot_strata_profile() → survey_fg_density_timeseries.png, survey_fg_density_timeseries_regional.png, survey_fg_depth_strata_profile.png.

  7. MEDIAS acoustic survey (Step 9, sub-steps 9a–9g) — load and collapse raw abundance/biomass records, map species codes via ASFIS, match to FG the same way as MEDITS, attach area (MEDIAS Handbook Table 1, hand-keyed MEDIAS_HANDBOOK_AREAS — as delivered this table only has Western Med entries, since that’s this example’s scope; extending to another region means adding that region’s own Handbook rows, with a bathymetry-derived 10–200 m fallback via compute_strata_area_by_area() covering any country/GSA combination the table doesn’t have a row for), compute region-wide FG and species density, then combine MEDITS + MEDIAS into one FG-level and one species-level table (averaged on Year/FG or Year/species overlap, overlaps flagged/printed). Outputs: medias_fg_annual_density_by_area.csv, medias_fg_annual_density_regional.csv, medias_fg_biomass_density_timeseries_regional.png, medias_fg_abundance_density_timeseries_regional.png, species_density_regional_combined.csv (contract file — read by lib_build_species_df_from_survey.R for 03_pbqb-traits.R).

  8. Excel export (Step 10) — survey_fg_annual_index.csv, survey_fg_annual_index_regional_combined.csv, then export_ecopath_ecosim_excel() writes sheets FG_spp_Ecopath, Ecopath, Ecosim, FG_spp_Ecosim into ecopath_ecosim_inputs.xlsx. Also writes a PB_QB_spp scaffold — reusing FG_spp_Ecopath’s own Species/ FG_num/Density/prop_sp_fg (renamed to PB_QB_spp’s convention: Biomass, prop_biomass_FG), with PB/prop_biomass_PB/QB/ prop_biomass_QB all blank and a Note column — so PB_QB_spp exists in the workbook after this script alone, without needing 03_pbqb-traits.R (Step 4) to have run first. This function has no PB/QB computation of its own (that’s entirely Step 4’s, from life-history parameters, not survey density), so the scaffold’s numbers are genuinely blank, not estimated. Running Step 4 afterward replaces the scaffold with the real sheet automatically (upsert_workbook_sheets() always fully replaces a same-named sheet). Guarded against clobbering the other way: if PB_QB_spp already has real (non-NA) PB values — i.e. Step 4 already ran against this exact workbook — re-running this script leaves it untouched rather than overwriting it with a blank scaffold again.

  9. Complete FG_spp_Ecopath/FG_lookup (Step 11) — union of observed + reference-catalog species, zero-fill species with no base-year density, attach taxonomy, defensive check for FGs with no species at all. Written via upsert_workbook_sheets().

  10. traits_ewe sheet (Step 12) — parse FG_WMed.xlsx’s traits_ewe sheet (alternating “N: Group Name” header rows / species rows, fill-down logic), reconcile against dataframe2, flag naming-variant and missing-traits species. Written via upsert_workbook_sheets().

  11. Finalize sheet order (Step 13) — finalize_workbook_sheet_order().

Script 2a — 02a_fisheries_multisource.R (optional, runs alongside Script 2)

Role: Optional additional Step 2 — requires Step 1 to have already run (reads strata_area_by_area.csv and the FG reference, same contract as Script 2/Script 4). Adds three genuinely different, already-assembled catch/effort sources on top of Script 2’s own FAO-GFCM source, so all four can be compared side by side and one of them selected to drive Fishing mortality (F) and PB = M + F downstream in Script 4 — without changing Script 4’s own F/PB math at all, only the input file it reads.

Why four sources, not one

None of the four is a strict upgrade over the others — each has real gaps of its own, which is why every one gets written into the workbook (DataSources_Catch) rather than silently picked for the user:

  • SAU (Sea Around Us) — reconstructed catch (adds back unreported/discarded/IUU catch on top of official landings), resolved to country × gear × species × year. The only source here with a real gear dimension, so Catches_by_Fleet (below) is built from SAU alone. Yield = SAU’s own reconstructed tonnes (already landings + discards + unreported/IUU, by SAU’s own definition).
  • SAU w/o unreported — the same SAU extract, filtered to reporting_status == "Reported". This is SAU’s own reporting-status split, not a clean “landings + discards” figure — kept as its own labeled source rather than mislabeled.
  • FishMIP — a SAU-derived calibration product (not independent of SAU), resolved to country × sector × functional group × year, with reported/IUU/discards already split out. No species dimension and no gear dimension on the catch side (gear only exists on FishMIP’s separate effort file — see Fishing_Effort_by_Fleet below). Yield = reported + discards (IUU deliberately excluded, kept as an audit column tonnes_incl_iuu, per the “landings + discards” definition used throughout this script). FishMIP’s own functional groups are not this pipeline’s FG scheme — see FISHMIP_FG_CROSSWALK_PATH below.
  • FAO-GFCM — this pipeline’s own existing source (Script 2’s output), passed through unchanged. Landings only (no discards), Division-resolution (not GSA), no fleet/gear dimension — same caveats as Script 2 itself.

Area scope caveat (same pattern as the GSA-12/Division mismatch already flagged for Script 2): SAU and FishMIP resolve to country/EEZ, not GSA. Restricting either one to “the same area as the survey” means restricting to the countries whose EEZs overlap that GSA range — an approximation, not an exact area match. A country with only a small coastal sliver inside the modeled GSA range still contributes its entire national catch/effort. This is unavoidable at these sources’ native resolution and is reported explicitly at runtime (TARGET_COUNTRIES_NOTE), not silently absorbed.

Processing steps

  1. Fetch the full EcoBase model list; save ecobase_model_list_full.csv.
  2. Filter geographically to the Mediterranean, using each model’s geographic_extent bounding box (not text/keyword matching on country/ecosystem names — more robust). Save ecobase_mediterranean_models.csv.

Script 4 — 03_pbqb-traits.R

Role: Pipeline Step 4 of 4 — run last. Requires Step 1’s species_density_regional_combined.csv. Optionally uses Step 2’s fg_catch_timeseries_<DATASET_VERSION>.csv (FG_YIELD_SOURCE toggle) and Step 3’s ecobase_literature_pb_qb_simple.csv — both degrade gracefully with a clear message if missing, they don’t hard-fail this script.

Every source’s own catch/effort still appears in the workbook’s DataSources_Catch/Catches_by_Fleet/Fishing_Effort_by_Fleet sheets (written by Script 2a) regardless of this setting — only this script’s own Fmort/PB = M+F chain follows whichever source is selected here.

Known, unresolved caveat (same root cause as Catches_Ecopath/ Catches_Ecosim below): Yield_FG’s denominator (area_total_km2, summed from strata_area_by_area.csv) is the survey’s GSA-filtered area, while its numerator (fg_catch_timeseries_*.csv’s Catch_t) is filtered by GFCM Division, which for the Western Med example covers GSA 1–11 plus GSA 12 — so Yield_FG, and therefore Fmort_FG and the fish PB it feeds, is a slight overestimate wherever this path is enabled. Not fixable from this side (GFCM’s catch data can’t be split below Division resolution); see the same caveat under Script 2 — 02_fao_catches.R for the full explanation. Also not implemented — no fleet or gear disaggregation: both Fmort_species (path A, inactive) and Fmort_FG (path B) are a single Yield/Biomass ratio lumped across the whole region and every gear/fleet that landed that species/FG — neither the landings_by_species_gsa_year.csv placeholder schema nor fg_catch_timeseries_*.csv carries a fleet or gear column, so there’s nothing here that could produce a fleet- or gear-specific F even once a real landings file is plugged in. See the matching note under Script 2 — 02_fao_catches.R for what a real fix would require (GFCM’s Operational-Unit data or STECF’s FDI database). Fmort itself stays single-fleet even where Catches_ sheets are split: unlike Catches_Ecopath/Catches_Ecosim (which can now be split by fleet via fleet_structure — see the “Single fleet by default; multi-fleet via an optional fleet_structure input” note under Script 2 — 02_fao_catches.R), this script never sees fleet_structure and computes Fmort_species/Fmort_FG from the same un-split fg_catch_timeseries_*.csv regardless. A genuinely fleet-specific F would need Yield split by fleet before this ratio, not just the Catches_ sheets split after the fact.

Trait fetching (Step 2a–2f) — select_best_rows() picks the best population-specific study per species from FishBase/SeaLifeBase multi-record tables, tiered: Western-Med locality keywords → broader Mediterranean keywords → most recent year → first available. extract_provenance() captures Locality/Year/Reference citation for each selected row (used later for the References sheet/CSV).

Adapting this pipeline to a different region

Everything below applies whether the target region is a single GSA, an arbitrary GSA subset, the whole Mediterranean GSA-by-GSA, or a fully custom (non-GSA) boundary.

Preferred method: source the scripts with pre-set options

01_biomass.R, 02_fisheries.R, 03_pbqb-traits.R, and 04_diets.R are source-able: every region/year/method knob each one uses (FILTER_AREAS, TARGET_COUNTRIES, YEAR_ECOPATH, START_YEAR/END_YEAR, TS_YEARS, DATASET_VERSION, FISHERIES_DATA_SOURCE, OUTLIER_METHOD, PB_QB_SELECTION_MODE, out_dir/pcloud_dir/git_dir, and a handful more — each script’s own “Configuration” section, under a comment block headed SOURCE-ABLE SCRIPT, lists exactly which variables it recognizes) is wrapped in if (!exists("VAR", envir = .GlobalEnv, inherits = FALSE)) VAR <- <default>. That means:

  • If a variable is already set in the calling environment before the script is source()-d, the script uses that value and skips its own default entirely.
  • If it is not set, the script falls back to its original Western Med default (GSA 1–11, 1994–2023) — running any of the three scripts on its own, exactly as before, is completely unchanged.

run_pipeline_demo.R is a driver script demonstrating this: it sets out_dir/pcloud_dir/git_dir once, then source()s 01_biomass.R → 02_fisheries.R → 03_pbqb-traits.R → 04_diets.R in that dependency order (01 must run first — see Adapting this pipeline to a different region below and each script’s own header comment for why; 04 specifically needs 01’s FG_spp_Ecopath sheet in the shared workbook for its species’ share-of-FG-biomass values, and is otherwise optional — diet composition isn’t needed for every run). It includes two ready-to-run examples, switched via a RUN_MODE flag at the top:

  • RUN_MODE <- "westmed_default" — sets nothing beyond the three paths; every script uses its built-in West Med default.
  • RUN_MODE <- "custom_example" — sets FILTER_AREAS <- 17:18, TARGET_COUNTRIES <- c("Italy", "Croatia", "Slovenia"), YEAR_ECOPATH <- 2005:2007, TS_YEARS <- 2000:2020, and START_YEAR/END_YEAR <- 2000/2020 as a worked Adriatic-GSA example — copy and adapt this block for any other region/year range, setting only the variables that need to differ from the West Med default.

YEAR_ECOPATH in particular is read by all three scripts and must stay consistent across them (it defines the single Biomass snapshot the PB/QB weights are computed against) — setting it once in the driver script before any of the three are sourced keeps them in sync automatically, which is easy to forget when editing each script’s hardcoded copy by hand.

This sourcing approach and the manual per-script editing approach described in the rest of this section are not mutually exclusive — the if (!exists(...)) guards mean a variable can still be hardcoded by editing the script directly (equivalent to always setting it), or left alone to pick up a caller’s override, on a variable-by-variable basis.

To model a different GSA or set of GSAs (Adriatic, Ionian, Aegean, Levant, or the whole basin), starting from 01_biomass.R as a template:

  • FILTER_AREAS — set to the target GSA number(s). No other GSA-based code in lib_survey_fg_density_functions.R hardcodes a Western-Med-only assumption — compute_strata_area_by_area(), weight_by_strata(), weight_by_area() etc. are all region-agnostic and operate on whatever area_ids/area_shp they’re given.
  • ALBORAN_GSAS/fix_alboran_longitude_sign() — a Western-Med-only correction (GSA 1–3); harmless no-op elsewhere, delete if not needed.
  • MEDIAS_HANDBOOK_AREAS/GSA_AREA_CROSSWALK — only populated for Western Med GSAs; add the target region’s own rows from the MEDIAS Handbook (or rely entirely on the bathymetry-derived 10–200 m fallback if MEDIAS data or handbook-reported areas aren’t available for that region).
  • out_dir/pcloud_dir/git_dir paths, and the raw MEDITS/MEDIAS/FG- reference file paths under them — point at the target region’s own data.
  • export_gsa_boundaries.R/fig_WMed_basemap.R — optional cartography only; edit the GSA-range filters if you want an equivalent map for the new region, otherwise skip both entirely (nothing downstream needs them).

To model a fully custom (non-GSA) region anywhere in the Mediterranean, use 01_survey_density_custom.R directly: set AREA_NAME, CUSTOM_AREA_TYPE ("bbox" or "shapefile"), and CUSTOM_BBOX/CUSTOM_SHAPEFILE_PATH to the target boundary — no GSA-specific code path is involved at all in this script (the Alboran-sign fix is present but is a documented no-op outside GSA 1–3).

Everything downstream of Step 1 — 02_fao_catches.R, 03b_ecobase.R, 03_pbqb-traits.R, and the shared library’s Excel-export/PB-QB functions — is already region-agnostic: they operate on whatever strata_area_by_area.csv and species_density_regional_combined.csv Step 1 produced, with no Western-Med-specific logic beyond 02_fao_catches.R’s area_filter_values (the FAO/GFCM division codes 37.1.1–37.1.3, which likewise need changing to match the target region’s own FAO division codes) and 03b_ecobase.R’s MED_LON_MIN/MAX/MED_LAT_MIN/MAX bounding box (already covers the full Mediterranean by default — Gibraltar to the Levant — so it does not need editing for a sub-region; narrow it only if you specifically want to exclude literature models from elsewhere in the basin).

Script 5 — 04_diets.R

Role: Pipeline Step 5, optional — builds an EwE diet-composition matrix (predator FG × prey FG) from the Mediterranean trophic metaweb database (data_entry_metaweb_empty.xlsx - currently an empty template, no DATA_ENTRY rows yet), collapsed from species-level predator-prey records up to the same Functional Group scheme used everywhere else in the pipeline. Auto-runs on source(), same convention as 01_biomass.R/02_fisheries.R/03_pbqb-traits.R — no separate function call needed afterward.

Dependency: must run after 01_biomass.R has written to the same ECOPATH_WORKBOOK_PATH — it reads biomass_proportion_by_species_fg.csv (01_biomass.R’s own native CSV output, output/biomass/ — not a workbook sheet) for each species’ share of its Functional Group’s total biomass (“proportion B”), which weights that species’ own diet more heavily within its FG’s combined diet the larger a share of the FG’s biomass it represents.
