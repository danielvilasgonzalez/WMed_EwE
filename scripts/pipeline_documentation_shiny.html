WarningBefore you start: this needs a live R session, and a one-time data cache

Unlike pipeline_documentation.qmd, this file is not a static document you can just open in a browser. server: shiny in the YAML above means it needs an actual R process running behind it - open it with quarto preview pipeline_documentation_shiny.qmd (or quarto serve) from a machine with R, Shiny, and this pipeline’s packages installed, or deploy it to shinyapps.io / Posit Connect / your own Shiny Server. Double-clicking a rendered .html file will not work - there’s no R behind a plain HTML file.

It also needs a one-time data cache before it can show your real MEDITS results - but you should never see a blank page waiting on that. The moment you open this app with no real cache yet, it shows a small synthetic demo dataset instead - fabricated GSAs, strata, functional groups and samples, built in-memory in milliseconds, no network or pCloud access needed - so every control and figure below is already populated and interactive on first load. A grey banner above the controls says plainly when you’re looking at that demo data rather than your real results.

Building the real cache is a separate, deliberate step - it is not attempted automatically by default, on purpose: a real 01_biomass.R run needs pCloud access and can take several minutes (GSA shapefile + bathymetry downloads, MEDITS loading, FG matching), and running that synchronously inside this document’s own startup code would block the page from rendering anything at all until it finishes - which looks identical to the app being broken if pCloud isn’t reachable from wherever quarto serve/quarto preview is running, or the run is simply slow. (If you’d rather have that automatic attempt back anyway - e.g. you know pCloud is reachable here and are fine waiting - set AUTO_BUILD_CACHE <- TRUE in this document’s setup chunk.)

The manual steps to build a real cache yourself:

  1. In 01_biomass.R’s Configuration section, temporarily set FILTER_AREAS to every GSA you have MEDITS data for (not just your usual region) and YEAR_ECOPATH/TS_YEARS to your full available year range - the widest extent you want this app to be able to explore later.
  2. Set SAVE_SHINY_CACHE_PATH <- "shiny_cache/survey_density_raw.rds" (relative to wherever 01_biomass.R writes out_dir) and run the script once, in full.
  3. Copy (or symlink) the resulting shiny_cache/survey_density_raw.rds to sit next to this .qmd file - CACHE_PATH in the setup chunk above expects it there.
  4. Revert FILTER_AREAS/YEAR_ECOPATH/TS_YEARS/SAVE_SHINY_CACHE_PATH back to their normal values for 01_biomass.R’s regular use - this cache is a frozen snapshot for THIS document only, not something the numbered pipeline scripts read back.

The cache is a snapshot either way: it does not update itself if the underlying MEDITS data changes. Repeat steps 1-3 (or, with AUTO_BUILD_CACHE <- TRUE, delete shiny_cache/survey_density_raw.rds and reload to trigger another automatic build) whenever you want it reflecting newer data.

What’s actually live here, and what isn’t

Changing the year range or the GSAs included below genuinely re-runs the pipeline’s own strata-weighting cascade (compute_fg_densities_by_stratum() → weight_by_strata() → weight_by_area()) against the cached per-sample data, and the four figures re-render from that real result - not a lookup of a pre-rendered image.

Three of the static form’s other options don’t carry over as live toggles, for reasons worth being upfront about rather than silently shipping a control that doesn’t really do anything:

  • DROP_OUTLIERS - outlier removal already ran once, at cache-build time (01_biomass.R’s own Step, before this document’s cache is saved). Toggling it here would need the raw pre-outlier-removal samples cached too, which this cache deliberately doesn’t keep (it’s already large enough as the full per-sample extent).
  • STRATA - weight_by_area() (needed for the region-wide figure) only implements the strata-weighted path; the unstratified (simple_area_density()) path has no region-wide aggregation wired up in the shared library today. This app always uses STRATA = TRUE to keep the region-wide figure working; the by-area figure would be the only one affected by STRATA = FALSE in any case.
  • Custom bounding box - re-deriving a custom polygon’s strata areas live would mean a fresh bathymetry download per input change, which is far too slow for an interactive control. GSA selection is live because STRATA_AREA_BY_AREA_FULL above is precomputed once for every GSA in the cache; a live bbox would need that recomputed on the fly instead.

The “Generate config block” panel at the bottom still works exactly like the static version - it always reflects your current picks above, ready to paste into 01_biomass.R, DROP_OUTLIERS/STRATA/bbox included, even though only year range and GSA selection also drive the figures live.
